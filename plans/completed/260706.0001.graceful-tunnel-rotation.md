# Task Breakdown — Graceful tunnel rotation (issue #1)

## Overview

Today the operator forces periodic streaming-exit rotation with a cron
`systemctl restart`, which hard-drops every live client connection. This plan
replaces that with an idle-gated, graceful rotation trigger: a new admin-only
HTTP endpoint `POST /v1/admin/rotate` on the existing API listener that asks the
`StreamingSupervisor` to swap its always-on device to a fresh random exit —
**break-before-make + settle** (teardown old → settle → build new) — only when no
streaming client sessions are in flight (`?force=true` overrides the gate and
rotates immediately). The streaming role self-limits to ≤1 live WireGuard session
at all times, mirroring the on-demand scheduler's teardown→settle→bring-up, so
rotation never adds a session and the host's 2-device ceiling holds with no
cross-role coordination.

The design is fixed by the orchestrator; this breakdown pins the exact files,
symbols, and race-free wiring. Four code tasks (three independent, one wiring)
plus a docs task.

Affected components (verified against the current tree):

- `internal/service/proxy.go` — `ProxyService` gains an `ActiveSessions() int64`
  gauge covering CONNECT tunnels **and** in-flight plain-HTTP forwards. The
  existing `tunnelCount`/`WaitTunnels` CONNECT-drain path (consumed by
  `internal/transport/httpserver/server.go:107` at shutdown) is left untouched.
- `internal/tunnel/lazy/supervisor.go` — `StreamingSupervisor` gains
  `RotateIfIdle(...)`, routed through its existing `loop` goroutine via a new
  `rotateCh` (mirroring `OnDemandScheduler`'s `Route`→`reqCh`→`Run` pattern in
  `scheduler.go`) so every `s.device` mutation stays serialized on one goroutine.
- `internal/transport/apiserver/{server.go,rotate.go}` — a transport-local
  `Rotator` interface, the `handleRotate` handler, the `/v1/admin/rotate` route,
  and an `Options.Rotator` injection point (with a `noopRotator` default,
  mirroring `noopCounter`).
- `cmd/vpntunnel/main.go` (+ new `cmd/vpntunnel/rotate.go`) — reorder so `svc` is
  built before `apiSrv`, construct the `rotateAdapter` closing over
  `supervisor.RotateIfIdle` + `svc.ActiveSessions`, inject via `Options.Rotator`.
- `CLAUDE.md`, `README.md` — routes table + operator runbook (curl, cron line,
  force vs gated). Systemd unit needs **no** change.

## Assumptions

- The trigger is HTTP-only (issue open-decision resolved to HTTP; no CLI flag, no
  signal, no `systemd` `ExecReload`).
- "Active" is scoped to the **streaming** `ProxyService` only. The
  `OnDemandScheduler` device is a separate concern and is intentionally **not**
  consulted for the gate. This is safe because the streaming role self-limits to
  ≤1 session (break-before-make + settle, Task 2): streaming ≤1 + on-demand ≤1 =
  host ≤2, so no cross-role coordination is needed (see R1).
- The streaming supervisor's device id is the `.conf` basename derivation
  (`tunnelIDFromPath`, e.g. `se-sto-wg-001`), already exposed non-secretly via
  `/v1/admin/health` `entry.ID` and startup logs. The rotate **response** returns
  only the 2-letter country code + status — no id, no endpoint, no key material.
- `RotateIfIdle` keeps the orchestrator's `busy func() bool` signature; the
  display-only `active_sessions` count in the skipped response is re-read from
  `svc.ActiveSessions()` in the adapter (harmless TOCTOU on an observability
  field — see Trade-off T6).
- Signature refinement vs the sketch: `RotateIfIdle` returns
  `(RotateResult, error)`, where the `error` is non-nil **only** on caller-`ctx`
  cancellation (client disconnect). The three real outcomes travel in
  `RotateResult`. This is the sole deviation from the sketched signature and does
  not touch the race-free core.

## Tasks

### Task 1: Add `ActiveSessions()` streaming-session gauge to `ProxyService`

- **Description:** Add an `activeSessions atomic.Int64` field to `ProxyService`
  (`internal/service/proxy.go`) and an exported `func (s *ProxyService)
  ActiveSessions() int64` returning `s.activeSessions.Load()`. Instrument
  `HandleHTTP` and `HandleCONNECT` so the gauge counts every in-flight streaming
  session. **Do not touch** `tunnelCount`, `tunnelNotify`, `tunnelMu`, or
  `WaitTunnels` — those keep their CONNECT-only drain semantics that
  `httpserver.Shutdown` (`internal/transport/httpserver/server.go:107`) relies on.
  A separate gauge (not a unified counter) is deliberate: HTTP forwards are
  drained by `http.Server.Shutdown`, hijacked CONNECT conns are not (which is why
  `WaitTunnels` exists), so conflating them would change the shutdown drain.

  **THE INVARIANT (state verbatim in the code comment on `ActiveSessions`):** in
  every handler path `activeSessions.Add(1)` strictly precedes the
  `DialContext`/`httpClient.Do` call; the matching `Add(-1)` runs on return for
  HTTP and only **after both conns are Closed** for CONNECT. No path leaks the
  counter.

  - **HandleHTTP:** increment immediately before `s.httpClient.Do(outReq)`
    (currently line 153), with a deferred decrement on the same two lines. The
    earlier returns (auth fail, non-absolute URI at ~124, request-build error at
    ~135) are non-dialing and must run **before** the increment so they neither
    count nor decrement. A pooled idle upstream conn outliving the handler is
    harmless — the client is no longer mid-transfer.
  - **HandleCONNECT:** increment immediately before `s.dialer.DialContext`
    (currently line 215), i.e. **after** the `net.SplitHostPort` validation (202)
    which must not count. Use a `sessionHandedOff` guard so every early-return
    error path between the dial and the goroutine launch (dial fail 216, no
    hijacker 229, hijack fail 240, write fail 259, flush fail 268) decrements
    exactly once, and the happy path hands ownership to the tunnel goroutine,
    which decrements inside its **existing** `defer` (284–291) — that defer runs
    after `clientConn.Close()`/`upstreamConn.Close()` (318–319).

- **Acceptance Criteria:**
   - [ ] `ProxyService.ActiveSessions() int64` exists, godoc documents the
     "increment-before-dial, CONNECT-decrements-after-both-Closed" contract.
   - [ ] `tunnelCount`, `WaitTunnels`, and their tests are unchanged; `make test`
     still green for `internal/transport/httpserver`.
   - [ ] `TestProxyService_ActiveSessions` (one top-level test, scenarios as
     `t.Run` subtests): HTTP success returns gauge to 0; HTTP non-absolute-URI
     early return never moves the gauge; HTTP upstream-error (502) returns gauge
     to 0; CONNECT happy path returns gauge to 0 only after the tunnel goroutine
     finishes; and **each** CONNECT error path (dial fail, no hijacker, hijack
     fail, write fail, flush fail) drives the branch and asserts the gauge
     returns to 0.
   - [ ] A mid-flight assertion proves the gauge is `1` while a CONNECT tunnel /
     HTTP forward is in progress (e.g. block the fake dialer/upstream, observe
     `ActiveSessions()==1`, unblock, observe `0`).
   - [ ] Any new mock/stub in the test file carries a `var _ Iface = &mock{}`
     assertion; `-race` clean.

- **Pitfalls:**
   - Registering the HandleHTTP decrement `defer` before the `IsAbs`/build-error
     returns would decrement on paths that never incremented (goes negative).
     Register it on the line **after** the increment, right before `Do`.
   - The CONNECT happy path must **not** decrement on handler return — ownership
     is the tunnel goroutine's. A bare `defer` there double-decrements. Use the
     `sessionHandedOff` flag.
   - Driving "hijack fail" / "write fail" / "flush fail" needs a custom
     `ResponseWriter` implementing `http.Hijacker` whose `Hijack()` errors, or
     returns a `net.Conn` whose `Write`/`Flush` errors. Inspect the existing
     `internal/service/proxy_test.go` doubles first; extend, don't duplicate. The
     load-bearing assertion is "gauge back to 0", independent of how the branch is
     reached.
   - `atomic.Int64` zero value is usable — no constructor change in
     `NewProxyService` is required.

- **Complexity:** Medium

- **Code Example:**
  ```go
  // HandleCONNECT — after the SplitHostPort validation, immediately before dial:
  s.activeSessions.Add(1)
  sessionHandedOff := false
  defer func() {
      if !sessionHandedOff {
          s.activeSessions.Add(-1) // every pre-handoff early return lands here
      }
  }()

  upstreamConn, err := s.dialer.DialContext(dialCtx, "tcp", target)
  // ... dial/hijack/write/flush error returns leave sessionHandedOff=false ...

  // at the handoff point (was: bare s.tunnelCount.Add(1)):
  sessionHandedOff = true
  s.tunnelCount.Add(1)
  go func() {
      defer func() {
          s.activeSessions.Add(-1) // after both conns Closed in the body below
          if s.tunnelCount.Add(-1) == 0 {
              s.tunnelMu.Lock()
              close(s.tunnelNotify)
              s.tunnelNotify = make(chan struct{})
              s.tunnelMu.Unlock()
          }
      }()
      // ... unchanged copy loop; clientConn.Close()/upstreamConn.Close() here ...
  }()

  // HandleHTTP — after the IsAbs check and request build, right before Do:
  s.activeSessions.Add(1)
  defer s.activeSessions.Add(-1)
  resp, err := s.httpClient.Do(outReq)
  ```

### Task 2: Add `RotateIfIdle` + serialized rotate handling to `StreamingSupervisor`

- **Description:** In `internal/tunnel/lazy/supervisor.go` add the exported
  rotation surface and route it through the existing `loop` goroutine so it never
  mutates `s.device` concurrently with the health-poll/reconnect logic.

  New exported types (place per File Declaration Order — exported types near the
  top):
  ```go
  type RotateOutcome int
  const (
      RotateRotated RotateOutcome = iota // device swapped to a fresh exit
      RotateSkippedActive                // gated + busy: nothing changed
      RotateUnavailable                  // no live device, build failed, or ctx cancelled during settle
  )
  type RotateResult struct {
      Outcome RotateOutcome
      Country string // lowercase 2-letter code; set only when Outcome == RotateRotated
  }
  ```

  New `SupervisorOptions` field `RotateSettle time.Duration` (required `> 0`,
  panic-guarded in `NewStreamingSupervisor` exactly like `HandshakeMaxAge`), a new
  exported constant `DefaultRotateSettle = 15 * time.Second` as the documented
  reference/fallback, and an unexported `rotateSettle` field on the struct. It is
  the mandatory pause between tearing the old streaming device down and building the
  new one, so Mullvad frees the old session before the new handshake — the
  streaming-role twin of the on-demand scheduler's `settleDelay` (`scheduler.go:355`).
  The supervisor takes a bare `time.Duration` and stays ignorant of on-demand
  config; main.go (Task 4) feeds it `cfg.API.VPN.Demand.SettleDelay`. Tests inject a
  tiny value (e.g. `10 * time.Millisecond`) and drive it with the fake `Clock`.

  New unexported plumbing: `rotateReq{force bool; busy func() bool; reply chan
  rotateReply}`, `rotateReply{result RotateResult}`, a `rotateCh chan rotateReq`
  field on the struct, allocated **unbuffered** in `NewStreamingSupervisor` (a nil
  channel would block forever). The reply channel is per-call and **buffered
  cap 1** so the loop never blocks replying to a caller that has already given up
  (identical rationale to `scheduler.go:162`).

  `RotateIfIdle(ctx, force, busy)` sends the req and waits for the reply, guarding
  both the send (against a stopped loop) and the reply (against caller-ctx
  cancellation):
  ```go
  func (s *StreamingSupervisor) RotateIfIdle(ctx context.Context, force bool, busy func() bool) (RotateResult, error) {
      reply := make(chan rotateReply, 1)
      req := rotateReq{force: force, busy: busy, reply: reply}
      select {
      case s.rotateCh <- req:
      case <-ctx.Done():
          return RotateResult{}, ctx.Err()
      case <-s.loopDone: // loop already exited (post-Stop) — do not hang
          return RotateResult{Outcome: RotateUnavailable}, nil
      }
      select {
      case r := <-reply:
          return r.result, nil
      case <-ctx.Done():
          return RotateResult{}, ctx.Err()
      }
  }
  ```

  `handleRotate` runs **on the loop goroutine** (the sole writer of `s.device`;
  the `RWMutex` only synchronizes against `DialContext` readers). It implements
  **break-before-make + settle** — tear the old device down (freeing the streaming
  session), settle so Mullvad releases it, then build the new exit and swap it in.
  The streaming role therefore holds ≤1 session at every instant, exactly like the
  on-demand scheduler's teardown→settle→bring-up, so rotation upholds the host's
  2-device ceiling with **no** cross-role coordination:
  ```go
  func (s *StreamingSupervisor) handleRotate(loopCtx context.Context, req rotateReq) {
      if !req.force && req.busy() { // cheap pre-check, no lock
          req.reply <- rotateReply{result: RotateResult{Outcome: RotateSkippedActive}}
          return
      }
      s.mu.Lock()
      if !req.force && req.busy() { // authoritative re-check UNDER the write lock
          s.mu.Unlock()
          req.reply <- rotateReply{result: RotateResult{Outcome: RotateSkippedActive}}
          return
      }
      if s.device == nil { // mid-backoff: nothing live to rotate
          s.mu.Unlock()
          req.reply <- rotateReply{result: RotateResult{Outcome: RotateUnavailable}}
          return
      }
      old := s.device
      oldID := s.deviceID
      s.device, s.deviceID, s.reporter = nil, "", nil // TEARDOWN under lock: new dials now see nil → unavailable
      s.mu.Unlock()
      if cerr := old.Close(); cerr != nil { // free the old Mullvad session
          s.logger().Warn("streaming supervisor: rotate old-device close failed", slog.String("err", cerr.Error()))
      }
      // settle so Mullvad frees the old session before the new handshake — upholds the ≤2-session host ceiling.
      select {
      case <-loopCtx.Done():
          req.reply <- rotateReply{result: RotateResult{Outcome: RotateUnavailable}} // shutdown mid-rotate; device stays nil, loop exits
          return
      case <-s.clock.After(s.rotateSettle):
      }
      newDev, id, rep, err := s.build(loopCtx, s.eligible.RandomPath())
      if err != nil {
          // device stays nil; the loop's d==nil branch backoff-rebuilds (self-heal).
          req.reply <- rotateReply{result: RotateResult{Outcome: RotateUnavailable}}
          return
      }
      s.mu.Lock()
      s.device, s.deviceID, s.reporter = newDev, id, rep // swap in — no re-check (bringing UP, not tearing down)
      s.mu.Unlock()
      newCountry := strings.ToLower(tunnel.CountryFromID(id))
      s.logger().Info("streaming supervisor: rotated tunnel",
          slog.String("old_country", strings.ToLower(tunnel.CountryFromID(oldID))),
          slog.String("new_country", newCountry),
          slog.String("new_tunnel_id", id))
      s.notifyChange("rotated", id, newDev) // reuse existing SourceStreaming notify path
      req.reply <- rotateReply{result: RotateResult{Outcome: RotateRotated, Country: newCountry}}
  }
  ```
  Notes baked into the mechanism:
  - `force=true` skips **only** the two busy checks; it still does
    break-before-make + settle. Force means "drop my active connections and
    rotate," **not** "burn a 6th session" — it must never exceed the budget either.
  - `RotateUnavailable` now covers three cases: no live device (mid-backoff), the
    post-settle build failed, or `loopCtx` was cancelled during the settle. The
    synchronous new-country is still reported on `RotateRotated` because `build`
    runs inline after the settle, before the reply.
  - The multi-second `build` and the settle wait both run with **no lock held**;
    only the brief teardown and the final swap take `s.mu.Lock()`. During
    teardown→settle→build the streaming device is nil and `DialContext` returns the
    existing "temporarily unavailable" `publicerror` — identical to a normal
    reconnect gap.

  Wire `rotateCh` into **both** `select` blocks of `loop` (the `d == nil` backoff
  wait at 274–282 and the live-device poll wait at 304–312), each as:
  ```go
  case req := <-s.rotateCh:
      s.handleRotate(ctx, req)
      continue // re-enter the for loop; poll/backoff timer of this iteration is abandoned
  ```
  Servicing `rotateCh` in the backoff select is required so a rotate during
  backoff is answered promptly (`RotateUnavailable`) instead of waiting out the
  backoff timer.

- **Acceptance Criteria:**
   - [ ] `RotateIfIdle(ctx, force, busy) (RotateResult, error)`,
     `RotateResult`, `RotateOutcome` (+ 3 constants) are exported with godoc
     documenting the concurrency contract, the break-before-make + settle order,
     the force semantics, and that the method returns a plain error (never
     `PublicError`), non-nil only on ctx-cancel.
   - [ ] `SupervisorOptions.RotateSettle` (required `> 0`, panic-guarded) and the
     exported `DefaultRotateSettle = 15 * time.Second` constant exist; `rotateCh` is
     allocated in `NewStreamingSupervisor`; reply channels are cap-1 buffered.
   - [ ] `s.device` is only ever mutated on the loop goroutine; the multi-second
     `build` and the settle wait both run with no lock held; the busy re-check and
     the teardown (`s.device=nil`) happen under the **same** `s.mu.Lock()` hold.
   - [ ] `TestStreamingSupervisor_RotateIfIdle` (one top-level test, subtests):
     - "rotates when idle" — teardown old → settle elapses on the fake clock → new
       device built → `Outcome=Rotated`, `Country` set, **old device Closed**, new
       device is a fresh `RandomPath` pick.
     - "skips when busy" — `Outcome=SkippedActive`, old device **still live and NOT
       Closed**, no teardown, no build.
     - "force ignores busy" — `Rotated` even with `busy()==true`, still
       break-before-make (old Closed, settle observed).
     - "build failure leaves device nil then loop self-heals" — 2nd build fails →
       `Unavailable`, device nil, then the loop's backoff branch rebuilds; assert an
       eventual live device.
     - "unavailable when no device" — first build never succeeded, loop in backoff →
       `Unavailable`.
     - "ctx-cancel during settle → `Unavailable` and old already Closed".
     - "caller ctx-cancel → `RotateIfIdle` returns `ctx.Err()`".
   - [ ] "settle gates the build": with the fake clock, assert the new `build` does
     **not** occur until `rotateSettle` has elapsed (advance the fake clock to
     drive it).
   - [ ] Subtest "concurrent dials during rotation" under `-race`: N goroutines
     acquire→`DialContext`→release with natural idle windows, one goroutine loops
     `RotateIfIdle(ctx, false, busyFromCounter)`; assert **no** dial ever hits the
     torn-down old device (dials during teardown→settle→build get the unavailable
     `publicerror`, never a closed-device panic) and the race detector is clean. A
     `force=true` variant asserts `-race` clean only — dropped in-flight dials are
     accepted under force.
   - [ ] Every mock/stub carries a `var _ Iface = &mock{}` assertion.

- **Pitfalls:**
   - `continue` inside a `select` case continues the enclosing `for` (correct
     here) — it does not merely exit the select.
   - The reply channel **must** be buffered cap 1: if the caller returned on
     ctx-cancel, an unbuffered reply send would block the loop forever.
   - `build` and the settle must use `loopCtx`, not the caller's request ctx — a
     client disconnect must not abort an in-flight rotation (the loop finishes it;
     the HTTP response is simply lost). A `loopCtx` cancel **during** the settle is
     the shutdown path: reply `Unavailable`, leave the device nil, let the loop
     exit.
   - Do **not** hold `s.mu` across `build` or the settle wait (would block every
     proxy `DialContext` for the whole ~15-20s window). Only the teardown and the
     final swap take the lock.
   - Race-freedom argument (put a condensed form in the godoc / a comment): the
     busy re-check **and** the teardown (`s.device=nil`) happen under the **same**
     `s.mu.Lock()` hold. Because every handler does `activeSessions.Add(1)`
     **before** its `DialContext` (Task 1 invariant, whose `RLock` therefore lands
     strictly after the increment), `activeSessions==0` observed under the write
     lock ⟹ no open connection to the old device ⟹ tearing it down drops nothing. A
     new dial racing us blocks on `RLock` until we unlock; by then `s.device==nil`,
     so it gets the "unavailable" `publicerror` and retries — it never grabs the
     torn-down old device. The final swap-in needs no re-check (it **adds** a
     device, it does not remove one).
   - `force=true` skips both busy checks but **not** the break-before-make + settle
     — it accepts dropping in-flight conns at the old device's `Close()`, yet still
     never presents a 2nd streaming session.
   - After a failed-build rotation the device is nil, so the loop's next iteration
     enters its `d==nil` backoff branch and rebuilds; `handleRotate` does not touch
     the loop's local `backoff` (reset to `reconnectMin` on the last healthy poll),
     so self-heal starts at min backoff.
   - A rotate settle+build blocks the loop's `stopCh` responsiveness until it
     completes or `loopCtx` aborts it — the settle's `select` honors `loopCtx.Done()`
     (not `stopCh`), and the build is bounded by the builder's dial timeout,
     identical in kind to the existing reconnect build (see R2).

- **Complexity:** Hard

### Task 3: Add the `POST /v1/admin/rotate` endpoint (apiserver)

- **Description:** In `internal/transport/apiserver` add a transport-local
  `Rotator` seam and the handler. Keep the transport layer free of any `lazy`
  import (consistent with how `handlers.Router`/`ZoneChecker`/`TunnelCatalog`
  keep `lazy` out — see `handlers/live_health.go`), so define the interface **and**
  a transport-local result type here; the `lazy`→transport mapping lives in the
  main.go adapter (Task 4).

  New file `internal/transport/apiserver/rotate.go`:
  ```go
  type RotationOutcome int
  const (
      RotationRotated RotationOutcome = iota
      RotationSkippedActive
      RotationUnavailable
  )
  type RotationResult struct {
      Outcome        RotationOutcome
      Country        string // set when Outcome == RotationRotated
      ActiveSessions int64  // set when Outcome == RotationSkippedActive
  }
  type Rotator interface {
      // Rotate triggers a graceful streaming rotation. force=false gates on
      // active sessions; force=true rotates regardless. err is non-nil only when
      // ctx was cancelled before the attempt completed.
      Rotate(ctx context.Context, force bool) (RotationResult, error)
  }
  ```

  Add `Rotator Rotator` to `apiserver.Options` (optional). In `New`, default a
  nil `Rotator` to a `noopRotator{}` that returns
  `(RotationResult{Outcome: RotationUnavailable}, nil)` — mirrors the
  `noopCounter` pattern at `server.go:414–420` so existing tests that don't wire
  it get a clean 503 instead of a panic. Add `var _ Rotator = noopRotator{}`.

  Handler `handleRotate` (method on `*Server`, delegating like `handleHealth`):
  - Method gate: **register the route methodless** —
    `mux.HandleFunc("/v1/admin/rotate", s.requireRole(RoleAdmin)(s.handleRotate))`
    in `buildMux` (next to the health route at 213–214) — and check
    `r.Method != http.MethodPost` inside the handler, replying
    `Allow: POST` + `handlers.WriteError(w, "method_not_allowed", 405, reqID)`.
    **Empirically verified:** with the `/` catch-all present, a method-scoped
    `POST /v1/admin/rotate` pattern makes a `GET` fall through to the catch-all
    (404), not 405 — so a real 405 requires methodless registration + a
    handler-side check. (This is why `POST /v1/admin/health` returns 404 today.)
  - Parse `force`: empty → `false`; a valid `strconv.ParseBool` value → that
    value; an invalid value → `handlers.WriteError(w, "bad_request", 400, reqID)`
    (loud failure on malformed admin input).
  - Call `s.rotator().Rotate(r.Context(), force)`; on non-nil err (ctx cancelled)
    just return (no body — the client is gone).
  - Serialize by outcome (`X-Request-Id` is already set by the `withRequestID`
    middleware at `server.go:252`, so the handler only sets `Content-Type`,
    `WriteHeader`, and the body):
    - `RotationRotated` → 200 `{"status":"rotated","country":"<cc>"}`
    - `RotationSkippedActive` → 200 `{"status":"skipped_active","active_sessions":<n>}`
    - `RotationUnavailable` → 503 `{"status":"unavailable"}`
    - unknown → 500 (defensive default)
  - Log the HTTP-level outcome at info (the authoritative old→new-country line is
    already emitted by `handleRotate` in Task 2; keep the transport log terse to
    avoid double-logging). Never log endpoint, key material, PSK, peer public key,
    or `TunnelHealth.Err`.

- **Acceptance Criteria:**
   - [ ] `Rotator`, `RotationResult`, `RotationOutcome`, `noopRotator` exist with
     godoc; `Options.Rotator` is optional with the noop default; existing
     `apiserver`/integration tests still compile and pass unchanged.
   - [ ] Route registered as admin-only; a `proxy`-role token → 403, no/invalid

   - [ ] `TestServer_handleRotate` (one top-level test, subtests): 405 for a

   - [ ] Stub `Rotator` in the test has `var _ Rotator = &stub{}`; `-race` clean;

   - [ ] No secret fields ever appear in the response or logs.

- **Pitfalls:**
   - Method-scoped registration silently yields 404-not-405 because of the `/`

   - `requireRole` runs before the handler, so the 405 test must send a valid

### Task 4: Wire the rotator in `cmd/vpntunnel/main.go`

- **Description:** The API server is constructed at `main.go:482` **before** the

## Risks

- **R1 — Session budget / 2-device ceiling — RESOLVED BY DESIGN.** The host must
  never present more than 2 concurrent WireGuard sessions (3 personal + 2 here =
  Mullvad's 5-session cap; each live WG session counts as one — source:
  `plans/completed/260623.0001.lazy-tunnels.md:649-651`, and
  `internal/tunnel/lazy/build.go:52` "callers own that invariant"). Because
  `api.vpn.demand.idle_ttl` defaults to 168h, the on-demand device is effectively
  always live, so streaming rotation must assume on-demand already occupies 1
  session. Task 2 uses **break-before-make + settle** (teardown old → settle →
  build new), so the streaming role holds ≤1 session at every instant — exactly
  like the on-demand scheduler's teardown→settle→bring-up. Streaming ≤1 + on-demand
  ≤1 = host ≤2 at all times, with no cross-role coordination. Make-before-break
  (the earlier sketch) is **rejected**: it transiently runs 2 streaming sessions,
  which with a live on-demand device is 3 host sessions = 6/5 total — a hard breach.
  Gating additionally on on-demand idleness is **not** a viable alternative
  (idle_ttl=168h ⟹ on-demand is ~never idle ⟹ rotation would ~never fire).
  Residual (smaller, unavoidable, accepted): rotating a **healthy** exit has a brief
  **new-connection** unavailability window (≈ settle + build, ~15-20s) — active
  connections are gated and unaffected; if the post-teardown build fails, streaming
  is briefly down until the loop's backoff-rebuild self-heals. Both are the honest
  cost of budget-safe rotation and are acceptable (idle-gated, cron-infrequent).
  Call the brief gap out for operator awareness in the PR.
- **R2 — Loop shutdown latency during a rotate settle+build.** While `handleRotate`
  runs, the loop is not in its main `select`, so it does not observe `s.stopCh`
  until the rotate returns; the settle's own `select` honors `loopCtx.Done()`
  (ctx-cancel) but not `stopCh`. In production shutdown cancels the run ctx (the
  same stop signal as `Stop()`), so the settle aborts promptly; a bare `Stop()` with
  no ctx-cancel waits out the in-flight settle+build (≤ `rotateSettle` + the
  builder's dial timeout). Same in kind as the existing reconnect build's stopCh
  latency, now +`rotateSettle`.
- **R3 — Abandoned `clock.After` timers.** When `rotateCh` fires the select instead
  of the poll/backoff timer, that iteration's timer is discarded (real-clock leak
  until it fires). Rotate is cron-infrequent → negligible; noted for completeness.
- **R4 — Client disconnect mid settle/build.** `RotateIfIdle` returns `ctx.Err()`
  (no HTTP body) on caller-ctx-cancel, but `handleRotate` runs on `loopCtx` and
  completes the rotation regardless (the reply lands in the cap-1 buffer, unread).
  Wasted response, not incorrect state; the next cron tick observes the rotated
  exit.
- **R5 — `force=true` drops the operator's own in-flight connections** at
  `old.Close()`. Intended per the decision; document so it is not mis-filed as a
  regression.

## Trade-offs

- **T1 — Separate `activeSessions` gauge, not a unified counter.** Chosen to keep
  `tunnelCount`/`WaitTunnels` CONNECT-drain semantics (relied on by
  `httpserver.Shutdown`) untouched. HTTP forwards are drained by
  `http.Server.Shutdown`; hijacked CONNECT conns are not — conflating them risks
  the shutdown drain for zero benefit.
- **T2 — Two-enum layer decoupling** (`lazy.RotateOutcome` +
  `apiserver.RotationOutcome`, mapped in the main.go adapter) over a shared type.
  Honors the codebase rule that the transport layer never imports `lazy` upward
  (as with `Router`/`ZoneChecker`/`TunnelCatalog`). Cost: a trivial 3-arm mapping
  switch in the adapter.
- **T3 — HTTP endpoint over CLI flag/signal** (issue open-decision): observable
  via logs, trivially callable from cron, reuses the existing API listener (no new
  port), and needs no systemd `ExecReload`.
- **T4 — Methodless route + handler method-check** to produce a real 405. The `/`
  catch-all defeats Go 1.22's automatic 405 for method-scoped patterns (verified
  empirically). Deliberate divergence from the health route's `GET `-prefixed
  registration, justified by the explicit 405 requirement.
- **T5 — Reorder `svc` before `apiSrv`** over a post-construction setter. Verified
  independent; constructor injection avoids a window where a half-wired server
  serves requests without a rotator.
- **T6 — Keep `busy func() bool`** (per the orchestrator sketch) and re-read the
  display-only `active_sessions` count in the adapter, rather than widening `busy`
  to `func() int64`. Keeps the supervisor ignorant of session counting; the
  count in the skipped response is observability-only, so the tiny TOCTOU is
  harmless. The gating decision itself is exact (the boolean re-check under the
  lock is authoritative).
- **T7 — Break-before-make + settle over make-before-break.** Make-before-break
  would give a zero-gap rotation but transiently runs a 2nd streaming session; with
  the ~always-live on-demand device (idle_ttl=168h) that breaches the 2-device host
  ceiling / 5-session Mullvad cap (see R1, and
  `plans/completed/260623.0001.lazy-tunnels.md:649-651`). The streaming role instead
  self-limits to ≤1 session by tearing down before building, mirroring the on-demand
  scheduler's settle (`scheduler.go:355`). Cost: a brief new-connection gap per
  rotation (active conns untouched). Recorded explicitly so a future reader does not
  "optimize" the gap away by reintroducing make-before-break.

race-stressed 10-20x):

  constructor already panics on `RotateSettle <= 0` and production wires

  lives in the `RotateSettle` field godoc.
- **Rebuild-failure logging.** The post-teardown build-failure path now logs a
  WARN with `tunnel_id` + `err`, matching the first-connect/reconnect branches,
  so a resulting `503 unavailable` is diagnosable rather than silent.

  cooldown; rapid calls churn the exit).

  mechanism (scope creep; the gate already makes rapid gated calls no-ops, and
