# Task Breakdown — Pragmatic DDD Restructure (issue #3 "DDD Style")

## Overview

Reorganize the `internal/` tree onto four visible DDD layers — `domain` /
`application` / `infrastructure` / `gateway` — while keeping every genuinely
cohesive subsystem intact as a sub-package. This is a **pure reorganization**:
zero behavior change, no new features, no logic edits beyond what a file move,
package rename, or import-path rewrite mechanically requires. The whole daemon
stays under `internal/` (no `pkg/`, no `sdk/`); `cmd/vpntunnel` and
`cmd/generatevpnconfig` stay put and only have their import paths rewritten.

The work is 54 non-test files + 51 test files. Because Go import paths are
absolute, a package cannot be half-moved: every commit that relocates or renames
a package must, in the same commit, rewrite **all** its importers. The change is
therefore executed as a small sequence of scripted, individually compile-green
commits (leaf→root), each verified with `go build ./... && make test`.

Three of the sixteen path rewrites also rename the package identifier and so
carry call-site selector churn (`tunnel.`→`domain.`, `service.`→`application.`,
`apiserver.`→`router.`). The remaining thirteen are pure path rewrites (import
string only; package clause and every selector unchanged). The single non-move
part of the plan is the deliberate extraction of `gateway/httpV1/routes/` and
`gateway/httpV1/dto/` (Tasks 7–8), scoped tightly and justified below.

## Assumptions

- Module path is `vpntunnel` (confirmed in `go.mod`), Go 1.26.
- Build tooling references only `./cmd/vpntunnel` and `./cmd/generatevpnconfig`;
  `make lint` has no forbidden-import list and no hardcoded `internal/` paths
  (confirmed). So only Go import paths, package clauses, and docs change.
- No local identifier is named `tunnel`, `service`, or `apiserver`; every
  `tunnel.` / `service.` / `apiserver.` occurrence is a package qualifier
  (verified by grep). Therefore the selector renames are unambiguous.
- `goimports` is available (or will be installed) for import-block dedup/cleanup.
- The green-lit target structure is the contract. Where it is silent
  (`publicerror`) or where the code contradicts the request (`dto/`), the
  resolutions in **Design Decisions** apply; the user may veto any of them.
- Tests are green at HEAD before Task 0 (baseline snapshot).

## Design Decisions (resolved — the load-bearing calls)

**D1 — Egress ports go to `domain`, exported.** `internal/tunnel/{dialer,country,
info,tunnelid}.go` import nothing internal (pure leaf). They fold into flat
`package domain`. The interfaces (`Dialer`, `DialerCloser`, `Resolver`,
`HealthReporter`) and value types (`TunnelHealth`, `TunnelInfo`) are shared by
**three** consumers — `application` (ProxyService), `application/lazy`, and
`gateway/httpV1/handlers` — and the value types cross package boundaries as
return values. The reference project's "unexported interface defined at the sole
consumer" pattern does not fit a three-consumer, shared-value-type port: it would
triplicate the interface and cannot share `TunnelHealth`/`TunnelInfo` as one
type. Exported domain types are the correct call. As `domain.Dialer`,
`domain.TunnelHealth`, `domain.CountryFromID`, `domain.TunnelID` the names read
cleanly. Verified: no identifier collisions across `domain.go` + the four folded
files (only `country.go`'s unexported `twoLowerLetters`; `domain.go` has no
private members).

**D2 — `internal/tunnel/` disappears entirely.** After the fold
(`{country,dialer,info,tunnelid}.go`→`domain`), the sub-packages
`lazy/`→`application/lazy` and `wireguard/`(+`wgconf/`)→`infrastructure/wireguard`,
nothing remains at `internal/tunnel/`. The directory is removed. No thin port
package is left behind — the ports live in `domain`.

**D3 — `publicerror` stays at `internal/publicerror/` (cross-cutting, not
folded).** Its API is deliberately terse — `New`, `Is`, `Error` — because it is
always read through the `publicerror.` qualifier. Folding it into flat `domain`
would produce `domain.New`, `domain.Is`, `domain.Error` (the last colliding
conceptually with the builtin `error`), or force an API rename
(`New`→`NewPublicError`) that changes the exported surface at 23 sites and
exceeds "mechanical." It is genuinely cross-cutting (imported by
`infrastructure/config`, `application/{proxy,lazy}`, `gateway/{router,handlers,
router/apitls}`) and semantically about *client-facing presentation of errors*,
which belongs to no single one of the four layers. Recommendation: **leave it in
place** (zero churn) as a sanctioned cross-cutting neighbor of the four layers,
documented as such in the Layer table.
- Rejected — fold into flat `package domain`: name degradation + non-mechanical
  API rename + surface change.
- Alternative if the user requires zero entries outside the four layers: move to
  `internal/domain/publicerror/` (sub-package, package clause unchanged,
  path-only rewrite of 23 sites, no name degradation). Not recommended, but
  strictly better than the flat fold.

**D4 — `application` package shape compiles cleanly, acyclically.** `proxy.go`
becomes `package application` directly under `internal/application/`; `lazy/` and
`asyncjob/` are sub-packages (a subdirectory is a separate package — no
conflict). Dependency edges after the move:
- `application` (proxy.go) → `domain`, `infrastructure/{auth,observability}`,
  `publicerror`. It does **not** import its own `lazy`/`asyncjob` children.
- `application/lazy` → `domain`, `infrastructure/{wireguard,wireguard/wgconf,
  notify}`, `publicerror`. This is the accepted DI-lite edge
  (application→infrastructure for the WireGuard builder). Acyclic: no
  infrastructure package imports `application` (verified — `wireguard`→`domain`
  only; `notify`→`domain` only).
- `application/asyncjob` → nothing internal (leaf).
`lazy` and `asyncjob` each have **two** consumer groups (`cmd` and `gateway`), so
the shared-tree placement is correct per the project's consumption rule.

**D5 — Gateway internal split (`router` / `httpV1/{handlers,routes,dto}`).** Map:
- **`gateway/router/`** (package `apiserver`→`router`): `server.go` (mux
  construction, `withRequestID`/`withAuth`/`requireRole`/`withAccessLog`
  middleware, `responseCapture`/`countingReader`, `ctxKey` + `*FromContext`,
  `Options`, `Server`, `noopCounter`), `requestid.go` (`newRequestID`),
  `rotate.go` (`Rotator`, `RotationResult`/`RotationOutcome` + constants,
  `noopRotator`, `handleRotate`, `parseForceParam`, `rotateResponse`†),
  `authtokens.go` + `authtokens_unix.go` + `authtokens_nonunix.go` (`Role`,
  `RoleAdmin`/`RoleProxy`, `Tokens`, `LoadTokens`, `TokenRoleCount`,
  `checkOwnerUID`). Plus `apitls/`→`gateway/router/apitls/` (package `apitls`
  unchanged, path-only).
- **`gateway/httpV1/handlers/`** (package `handlers`, path-only): all seven
  handler files move wholesale, including `WriteError` (envelope.go).
- **`gateway/httpV1/routes/`** (NEW): the five route patterns registered inline
  in `server.go`'s `buildMux`, extracted as exported string constants.
- **`gateway/httpV1/dto/`** (NEW): the response **structs** only.
  **Correction to the request:** of the four bodies named, only two are Go
  structs — `healthResponse`+`entry` (health.go) and `rotateResponse`†
  (rotate.go). The error envelope (`WriteError`) marshals an inline
  `map[string]string` and is a *response-writing helper*, not a DTO — it stays in
  `handlers`. The tunnels catalog is an inline `map[string][]string` in
  `tunnels.go` (no struct) — it stays inline. So `dto/` holds exactly
  `dto.HealthResponse`, `dto.HealthEntry`, `dto.RotateResponse` (exported).
- Layering after the split (all acyclic, all pre-existing directions preserved):
  `router` → `handlers` → {`dto`, `application/{lazy,asyncjob}`, `domain`,
  `infrastructure/ipdeny`, `publicerror`}; `router` → {`dto`, `routes`,
  `infrastructure/config`, `domain`, `application/asyncjob`,
  `infrastructure/observability`}. `handlers` does not import `router` (verified).

Justification for the one non-move part (routes/ + dto/): CLAUDE.md pins the v1
wire contract as *frozen* (`/v1/admin/health` body "is fixed"; rotate shapes
"exactly as documented"; the route table). A frozen contract is precisely the
"named cross-cutting invariant → centralize once" case in the project's own Code
Organization Principles, which overrides the default single-consumer placement.
Centralizing paths in `routes/` and response structs in `dto/` makes the frozen
contract reviewable in one place. This is the only place the exported surface
changes (unexported→exported, all module-internal — no external break) and the
only edit beyond a literal move. If the user prefers the strictest zero-diff
reorg, Tasks 7–8 can be deferred to a follow-up plan without affecting Tasks 0–6.

**D6 — Migration order & mechanism.** Leaf→root, several individually-green
commits (Execution Order). One scripted atomic commit is possible but harder to
review across 105 files; the staged sequence is recommended. Rewrites are
deterministic (tables below): `git mv` the directory, `sed` the import-path
string across all importers, and for the three renames `sed` the package
qualifier, then `goimports -w` to tidy. Hand-editing 105 files is rejected as
error-prone.

**D7 — Docs.** CLAUDE.md Layer table is rewritten (Task 9). The "Code
Organization Principles" prose **survives** — the pragmatic choice keeps
subsystem cohesion, so "flat per-concern packages" now applies *within* each
layer (infrastructure holds flat `config/auth/wireguard/observability/notify/
ipdeny`; application holds flat `proxy` + `lazy` + `asyncjob`), and "inline
composition root, no shared bootstrap" is unchanged (`cmd/vpntunnel/main.go`
stays the wiring root). One clarifying sentence is added, nothing is deleted.
README references only `./cmd/vpntunnel/` build paths (no `internal/` paths) and
needs only a prose sweep for renamed package names.

## Rewrite Table 3 — package-qualifier selector renames (the three renames)

Each qualifier is unambiguous (no shadowing variable). Run the qualifier `sed`
across all importers, then `goimports -w .`.

| Rename | Command (over importer files) | Consumer symbols covered |
|---|---|---|
| tunnel→domain | `sed -i 's/\btunnel\./domain./g'` | `Dialer, DialerCloser, Resolver, HealthReporter, CountryFromID, TunnelHealth, TunnelInfo, TunnelID` |
| service→application | `sed -i 's/\bservice\./application./g'` | `NewProxyService, ProxyService, ProxyServiceOptions, ErrFallbackMessage, IsLoopbackRemote` |
| apiserver→router | `sed -i 's/\bapiserver\./router./g'` | `New, Options, Server, LoadTokens, Tokens, TokenRoleCount, Role, RoleAdmin, RoleProxy, Rotator, RotationResult, RotationOutcome, RotationRotated, RotationSkippedActive, RotationUnavailable` |

The moved package's OWN files change their package clause via
`sed -i 's/^package apiserver$/package router/'` (and the `apiserver_test` /
`domain_test` / `application_test` external-test variants, if any). A safer
AST-based alternative to the qualifier `sed` is per-symbol
`gofmt -r 'tunnel.Dialer -> domain.Dialer' -w .` (repeat per symbol) — use it if
any importer is later found to shadow a qualifier.

## Risks

1. **`application/proxy.go` double-`domain` import (Task 6).** It is the sole file
   importing both `domain` and `tunnel`; the fold collides the two imports. If
   `goimports -w` is skipped, the build fails with `duplicate import`. Mitigation:
   the Task-6 script ends with `goimports -w .`; the checkpoint build catches it
   immediately. Blast radius: one file, obvious failure. **Highest-probability
   snag, lowest severity** (compiler-caught).

2. **Silent selector corruption from a mis-scoped `sed` (Tasks 4–6).** A
   `\bX.\b` qualifier rename that accidentally matches a comment or, worse, a
   shadowing identifier would change meaning without a compile error only if the
   shadow has a same-named member. Mitigation: Task 0 proves no shadow exists;
   prefer per-symbol `gofmt -r` if any importer is later found to shadow; the
   `-race` suite is the behavioral backstop. **Medium severity, low probability.**

3. **`routes/`/`dto/` extraction drifts the frozen wire contract (Tasks 7–8).**
   Re-typing struct fields/JSON tags or the `*int64` pointer on
   `RotateResponse.ActiveSessions`, or the method prefix on a route constant,
   would silently change a response shape or route match. Mitigation: acceptance
   criteria pin byte-identical tags/values; the existing `integration_test.go` /
   `health_test.go` / `rotate_test.go` assertions are the contract guard and must
   pass unedited. If risk tolerance is low, defer Tasks 7–8 (D5). **High severity
   if missed, but test-guarded.**

Lesser risks: `git mv` history breakage (mitigated — use `git mv`, verify
`--follow`); missed `generatevpnconfig` build (Task 10 builds it explicitly);
stale doc paths (Task 9 grep-gates).

## Trade-offs

- **Ports in `domain` (exported) over consumer-defined interfaces (D1):** chose
  shared exported ports because three consumers share both the interfaces and the
  value types; the reference's per-consumer-unexported pattern would triplicate
  the interface and cannot share `TunnelHealth`/`TunnelInfo`. Cost: `domain`
  carries interfaces, not just data — accepted, they are pure and stdlib-only.
- **`publicerror` stays standalone over folding into `domain` (D3):** chose zero
  churn + honest cross-cutting layering because its terse API (`New`/`Is`/`Error`)
  degrades under a `domain.` qualifier and folding would force a non-mechanical
  API rename. Cost: one directory sits beside the four layers — documented as a
  sanctioned cross-cutting neighbor, not hidden.
- **`routes/` + `dto/` extracted over left inline (D5):** chose to honor the
  green-lit structure and centralize the CLAUDE.md-pinned frozen v1 contract,
  which the project's own "named invariant → centralize" principle sanctions over
  default single-consumer placement. Cost: the only exported-surface change and
  the only non-move edit — isolated to Tasks 7–8, deferrable if the team wants a
  strictly zero-diff reorg.
- **Several green commits over one atomic commit (D6):** chose staged leaf→root
  commits for reviewability of 105 touched files; each is independently green and
  bisectable. Cost: more commits, and `cmd/vpntunnel/main.go` appears in six
  diffs — accepted for review clarity.
- **`gateway`-layer split (`router` vs `httpV1/*`) over a flat `gateway`
  package:** chose to keep the transport composition (`router`) separate from the
  versioned API surface (`httpV1`) so a future `httpV2` slots in beside `httpV1`
  without touching `router`; matches the green-lit contract. Cost: one extra
  directory level — accepted, it encodes the API-version seam.
