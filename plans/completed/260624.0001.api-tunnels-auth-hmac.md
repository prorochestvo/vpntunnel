# Task Breakdown

## Overview

A breaking API + config change to `vpntunnel`, acceptable because there is a single
hand-authored production host. Five locked decisions are implemented end to end:

1. **Tunnel routing by path id.** Replace `/v1/proxy/{scheme}/{rest...}` plus the
   `X-Tunnel-Id` header with `/v1/tunnels/{id}/proxy/{scheme}/{rest...}`. The tunnel is
   a path segment `{id}`, not a header; `X-Tunnel-Id` is removed end to end. `{id}` is
   the HMAC tunnel id from decision 3.
2. **Two-role model.** Remove `RoleDeploy`. Two roles remain: `RoleAdmin` (full) and
   `RoleUser` (renamed from `RoleProxy`). `/v1/admin/*` → admin only; `/v1/tunnels` and
   `/v1/tunnels/{id}/proxy/...` → user OR admin. The release health-check switches from
   a `DEPLOY_TOKEN` secret to an `ADMIN_TOKEN` secret.
3. **HMAC tunnel ids + catalog `/v1/tunnels`.** `id = HMAC-SHA256(key, config_basename)`,
   hex-encoded, stable per host. The key is referenced by a new top-level
   `tunnel_id_hmac_key_file` (0600 file, 32 random bytes), generated on first run if
   absent. The key is key material (never logged); the derived hex id is public.
   `/v1/tunnels` returns the FULL discovered set grouped by country as a map
   `country -> [ids]` (no health/handshake fields — it is a catalog). `?country=us,uk`
   narrows the result.
4. **Config / migration.** Remove `api.auth.deploy_token_file`; rename
   `api.auth.proxy_token_file` → `api.auth.user_token_file`; add top-level
   `tunnel_id_hmac_key_file`. `proxy.json` stays non-secret (the key is a file reference).
   Migration probes fire for the removed and renamed keys. Rewrite
   `configs/proxy.example.json` and update `CLAUDE.md`.
5. **Scope guard.** Do NOT change the dual-mode listener, the streaming country-split,
   folder discovery, or anything from plans 004/006 beyond what these decisions require.

The work is decomposed into 14 waves (W1–W11, W13–W15; the wave formerly numbered W12 —
dead-code removal in `live_health.go` — is folded into W11 because deleting `tunnelLister`
from `tunnels.go` breaks a compile-time assertion in `live_health.go` in the SAME package,
so both must land in one commit) grouped for maximum parallelism. The structural
spine: **config field rename + new field** (W1) and the **HMAC id helper** (W2) are
foundational; almost everything routing/roles/handler-shaped depends on them. Three
files are edited by multiple concerns and therefore become **single-writer merge waves**:
`internal/transport/apiserver/server.go` (routing path + role allow-lists + tunnels-handler
source) and the apiserver test pair `server_test.go` + `integration_test.go` (paths +
token field names + role-assertion flips).

### Ground-truth notes (verified against the current tree, not assumed)

- `EligibleSet` (`internal/tunnel/lazy/eligible.go`) is a single type backing BOTH the
  streaming set (`NewEligibleSet`, country-filtered, `RandomPath` only) AND the full set
  (`NewFullSet`, used by the scheduler via `Lookup`/`IsEligible` and by the API
  `ZoneChecker`). It keys `byID map[string]string` on the config basename. `NewFullSet`
  delegates to `NewEligibleSet` with a nil filter. Re-keying the full set by HMAC id
  changes the shared struct; the streaming set must stay keyed by basename.
- `Lookup(id)(string,bool)` / `IsEligible(id)bool` / `RandomPath()string` / `Len()int`
  take/return an opaque string. Keeping those signatures stable means only the *meaning*
  of the id changes; the scheduler and proxy handler compile unchanged once routing passes
  the HMAC id. This is what makes the routing waves parallelizable against the re-keying.
- `tunnel.CountryFromID` (`internal/tunnel/country.go:24`) returns an **uppercase**
  two-letter code (its godoc says "The returned code is uppercase"; `twoLowerLetters`
  ends in `return strings.ToUpper(s)`) or `""` for unparseable. The catalog grouping and
  the `?country=` filter must normalize to the SAME case — wrap `CountryFromID` in
  `strings.ToLower` when storing the country (W5) so catalog keys and the `?country=`
  filter are on the same case plane, and lower the query tokens to match. The existing
  streaming-set filter already does exactly this (`eligible.go:67`:
  `strings.ToLower(tunnel.CountryFromID(id))`). The unparseable bucket key is the fixed
  lowercase string `"zz"` (same case plane as the country keys, so `?country=zz` matches).
- `/v1/tunnels` is currently fed by `LiveHealthModel.Tunnels()` (live-only). Decision 3
  makes it the FULL catalog, so the handler source changes from `LiveHealth` to the full
  set, and `LiveHealthModel.Tunnels()` + `infoFromHealth` + the
  `var _ tunnelLister = (*LiveHealthModel)(nil)` assertion (`live_health.go:82`) become dead.
  Because `tunnelLister` lives in `tunnels.go` and that assertion lives in `live_health.go`
  in the SAME package, removing the interface and the assertion MUST happen in one commit —
  so the dead-code deletion is folded into **W11** (not a separate later wave), and `Reports()`
  stays for `/v1/admin/health`.
- `cmd/vpntunnel/main.go:287` calls `lazy.NewFullSet(discovered, configDir)` between
  `configDir := filepath.Dir(configPath)` (:270) and the scheduler wiring. The HMAC key
  load lands there, and `NewFullSet` gains a `hmacKey []byte` parameter.
- `server.go New()` wires `NewTunnelsHandler(opts.LiveHealth, log)` (:90) and passes the
  full set as `opts.ZoneChecker` (:47, fed `fullSet` at `main.go:440`). `ZoneChecker` is
  typed as the narrow `handlers.ZoneChecker` (IsEligible only) and has no `Entries()`, so
  a new `Options.TunnelCatalog` field carrying the full set is required for the handler.
- `tunnel.TunnelID` does NOT exist yet (grep confirmed). `internal/tunnel` does not import
  `lazy` (one-way), so the new helper lives in `internal/tunnel` beside `CountryFromID`
  and both `lazy` (keying) and routing (path mapping) can call it without a cycle.
- The async replay path (`serveAsync`, `proxy.go:270`) rewrites `asyncReq.URL` before the
  job is stored; `ZoneRoutingForwarder.Forward` (`zone_forwarder.go:72`) currently recovers
  the id from `X-Tunnel-Id`. Once the id is a path segment AND the URL is rewritten, the id
  is lost by replay time — so the validated id is stamped onto an internal header
  (`X-Vpntunnel-Tunnel-Id`) on the clone, read back by the forwarder, and added to
  `serviceHeaders` so both sync and async strip a client-supplied fake.

## Assumptions

- The HMAC key is **generated on first run** when the file is absent (write 0600; do NOT
  rewrite `proxy.json`). This is the locked behavior; it is trivially flippable to
  operator-provided-only by deleting the generate branch and returning a `publicerror` on
  absence — noted in W3.
- `tunnel_id_hmac_key_file` is **optional with a default** (`./auth/tunnel-id.key`), NOT
  required: an absent field is a valid steady state because the daemon generates the key.
  This avoids touching the 40+ existing config fixtures and `proxy.example.json`'s required
  set. An explicit empty string is rejected.
- The HMAC id is non-secret: it travels in `/v1/tunnels` JSON, the URL path, and the access
  log. Only the HMAC **key** is banned from logs. The existing `tunnel_id` slog fields log
  the basename and remain fine.
- `proxy.json` stays non-secret: the new field is a path reference, so there is NO 0600
  enforcement on `proxy.json` itself. The 0600/generate/never-log logic lives in the key
  loader (W3), not in config.
- `tunnel.CountryFromID` returns uppercase; wrap it in `strings.ToLower` when storing in
  `entry.country` (W5) so catalog keys and the `?country=` filter are on the same case
  plane. The catalog and the query filter both normalize to lowercase, and the unparseable
  bucket is the lowercase literal `"zz"` (so `?country=zz` matches it through the same
  filter path). (If a future maintainer wants uppercase country keys, that
  is a separate change to both the grouping and the filter, not just `CountryFromID`.)
- The `Prefix*` error-vocabulary constant VALUES (`unknown_zone:`, `zone_bring_up_failure:`)
  in `scheduler.go` are classified on by `zone_forwarder.go` and stay byte-for-byte; only
  internal vars/log keys are renamed.
- All persisted text (commit messages, plan, docs, comments) is English and profanity-free.

### Task 2 (Wave 2): Add `tunnel.TunnelID(key, basename)` HMAC id helper

- **Goal:** One pure, tested function deriving the hex HMAC tunnel id from a config basename.
- **Files:**
  - `internal/tunnel/tunnelid.go` (new)
  - `internal/tunnel/tunnelid_test.go` (new)
- **Description / change spec:** New file `internal/tunnel/tunnelid.go`:
  ```go
  // TunnelID returns the stable per-host HMAC tunnel id for a config basename.
  // basename is the .conf filename without the ".conf" suffix (the same string
  // CountryFromID consumes). The returned id is lowercase hex, 64 chars, and is
  // NON-secret (published in /v1/tunnels and used as the {id} path segment). key
  // is key material and must never be logged.
  func TunnelID(key []byte, basename string) string {
      h := hmac.New(sha256.New, key)
      h.Write([]byte(basename))
      return hex.EncodeToString(h.Sum(nil))
  }
  ```
  Imports `crypto/hmac`, `crypto/sha256`, `encoding/hex`. No I/O, no logging. Lives beside
  `CountryFromID` (no import cycle — `internal/tunnel` does not import `lazy`). File
  Declaration Order: exported func + godoc at top.
- **Tests** (`internal/tunnel/tunnelid_test.go`): `TestTunnelID` with `t.Parallel()` subtests
  (each also `t.Parallel()`): (1) deterministic for same key+basename; (2) differs by
  basename (`se-sto-wg-001` vs `de-fra-wg-001` under one key); (3) differs by key (same
  basename under two distinct 32-byte keys); (4) output is 64 lowercase hex chars
  (`len==64` and matches `^[0-9a-f]{64}$`); (5) empty basename still produces a 64-char id.
- **Acceptance criteria:**
  - [ ] `make test` green; `TestTunnelID` covers the five scenarios as subtests of one top-level func.
  - [ ] No logging anywhere in the file; godoc states id is non-secret and key is key material.
  - [ ] `make lint` green.
- **Pitfalls & edge cases:**
  - Do NOT use `sha256.Sum256(key||basename)` — that is not an HMAC and is length-extension-weak; use `crypto/hmac`.
  - Never log `key` in this file. Keep the function pure so `lazy` and routing can both call it without a circular import.
- **Complexity:** Easy
- **dependsOn:** none
- **PARALLELIZABLE:** true (brand-new files, disjoint from everything).

## Risks

- **Three-way collision on `server.go`** (routing path + role args + tunnels source). Mitigated
  by merging all three into the single-writer **W10**. If split across engineers, the mux build
  panics or the tunnels handler reads the wrong source. This is the highest-complexity wave —
  budget accordingly.
- **`config.go` ↔ `authtokens.go` compile coupling.** W1's struct rename breaks `authtokens.go`
  immediately. `go build ./...` is RED between W1 and W4 — they MUST be one commit/batch. Do
  not push W1 alone.
- **`EligibleSet` re-key blast radius (W5).** Renaming `byID` → `byKey` breaks the scheduler,
  proxy handler, and health at compile time. Keeping `Lookup`/`IsEligible`/`RandomPath`/`Len`
  signatures stable confines the change to id *meaning*. A regression here means every proxy
  request 400s `unknown_tunnel` (id source and id key disagree) — the W10 integration test
  (path → Route → forwarder over the live mux with HMAC ids, id computed via `tunnel.TunnelID`)
  is the safety net.
- **HMAC key clobber / silent id rotation.** If the key file is overwritten, every tunnel id
  changes and existing clients break. `O_CREATE|O_EXCL` (W3) prevents clobber; the load branch
  never writes. Back up `/opt/vpntunnel/auth/tunnel-id.key` like a private key.
- **`ADMIN_TOKEN` secret not created before the next tag.** W14 renames the secret reference;
  the PRIME-scoped `ADMIN_TOKEN` GH secret must exist before the next `v*` tag or the deploy
  job fails on the health-check (60s timeout → exit 1). **Operator action item**, flagged in
  W14 and CLAUDE.md.
- **Country-case mismatch.** `CountryFromID` returns UPPERCASE; W5 must wrap it in
  `strings.ToLower` when storing `entry.country`, and W11's `?country=` filter lowers its
  tokens, so catalog keys and the filter land on the same lowercase plane. Skipping the W5
  wrapper stores `"SE"`/`"DE"` as catalog keys while the filter matches `"se"` — a silent
  `{}` for every query, caught only at W11 test time (the `{"se":[…],"de":[…]}` assertion
  fails), not at compile time. The `zz` bucket (fallback for unparseable basenames) is
  lowercase like every other key, so `?country=zz` matches it — tested explicitly.
- **Async id loss after URL rewrite.** `serveAsync` rewrites the URL before storage; without
  the internal-header stamp (W7) the forwarder (W8) cannot recover the id at replay time and
  every async job 400s `tunnel_required`. The stamp-on-clone-before-`SubmitOrFetch` ordering is
  load-bearing and covered by a W9 subtest.
- **Mux pattern overlap panic.** A stray `/v1/tunnels/{id}` registration would panic the Go
  1.22 mux at wiring time. W10's spec forbids it explicitly.

## Trade-offs

- **Single-writer merge waves (W10) over maximal wave splitting.** Splitting routing/roles/source
  into three waves on one file would force artificial sequential barriers and risk concurrent
  edits to the same function. Merging them into one wave trades a larger wave for zero
  intra-file conflict and a clean single review. The lenses remain distinct in the spec.
- **HMAC key optional-with-default + generate-on-first-run over required-and-operator-provided.**
  Default-and-generate keeps every existing config fixture and `proxy.example.json` valid (no
  lockstep churn) and gives a zero-touch first boot. The cost is a generated secret the operator
  must learn to back up. Flip to operator-provided is one branch deletion (noted in W3).
- **`proxy.json` stays non-secret (key by file reference) over inlining the key.** A file
  reference keeps `proxy.json` safe to commit and inspect, and isolates the 0600/never-log
  discipline to one loader. The cost is one more file to manage.
- **New `tunnel.TunnelID` in `internal/tunnel` over a method on `EligibleSet` or a `lazy` helper.**
  Placing it beside `CountryFromID` lets both `lazy` (keying) and routing/tests (e2e id
  computation) call it with no import cycle and keeps it a pure, trivially testable function.
- **`/v1/tunnels` as a pure catalog (no health) over reusing the live-health projection.**
  Decision 3 wants the full discovered set; health belongs to `/v1/admin/health`. Separating the
  two removes the dead `LiveHealthModel.Tunnels()` path (deleted inside W11, in the same commit
  as the `tunnels.go` interface removal, because the `tunnelLister` compile-time assertion lives
  in `live_health.go` in the same package) and prevents the catalog from leaking handshake state.
  The cost is a second source wired into `server.go` (`TunnelCatalog`).
- **Keeping `Prefix*` error-vocabulary constant VALUES unchanged while renaming internal
  `zoneID`→`tunnelID` (W6).** Renaming the values would be a cross-file break with
  `zone_forwarder.go`'s classifier for zero user benefit. Cosmetic rename only; the shared
  contract is preserved.
