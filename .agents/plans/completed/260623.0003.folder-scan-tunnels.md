# Task Breakdown

## Overview

Replace the explicit `upstream.configs` list with automatic folder-scan discovery.
The daemon scans `<configDir>/tunnels/` for top-level `*.conf` files and uses every
one it finds as the raw config set. The existing `upstream.allowed_countries` filter
then narrows that set, and the existing streaming-supervisor / on-demand-scheduler
random pick chooses among the eligible result. The `configs` JSON field is removed
from the schema entirely (not an optional override) — the daemon always folder-scans.

The change is deliberately narrow:

- A new discovery function returns the `[]string` of config paths that today comes
  from `cfg.Upstream.Configs`. Everything downstream (`NewEligibleSet`,
  `VerifySingleKey`, the eligible set, the supervisor, the scheduler) is fed from
  that slice and needs no behavioural change.
- `proxy.json` stays. Only the `upstream.configs` field is removed;
  `upstream.allowed_countries`, `streaming`, `ondemand`, `api`, `auth`, etc. all
  remain. Moving config to env / killing `proxy.json` is explicitly out of scope.

Code map (verified against the current tree on `v2-squashed`):

- `internal/config/config.go` — `rawUpstream.Configs`, the `Upstream.Configs`
  field, the `toConfig` copy (line ~466), and the validate block (lines 793-800)
  are the only places `Configs` is parsed/validated. `AllowedCountries` lives in
  the same structs and stays.
- `cmd/vpntunnel/main.go:185-193` — `lazy.NewEligibleSet(cfg.Upstream.Configs, configDir, ...)`
  and `lazy.VerifySingleKey(cfg.Upstream.Configs, configDir, opLog)`. These are the
  two call sites that must instead receive the discovered slice.
- `internal/tunnel/lazy/eligible.go` (`NewEligibleSet`) and `verify.go`
  (`VerifySingleKey`) — both already take `[]string` + `configDir`, both already
  resolve relative paths to absolute via `filepath.Abs`, both already warn-skip
  unparseable configs (verify.go) or drop unmatched countries (eligible.go). No
  change required.
- `internal/tunnel/country.go` (`CountryFromID`) — unchanged; a `.conf` whose
  basename is not `mullvad-<cc>-...` / `<cc>-...` yields `""`, which matches no
  entry in a non-empty `allowed_countries` and is silently dropped (existing
  behaviour, exercised by the new tests).
- `cmd/generatevpnconfig/main.go:200,236` — operator help text says
  "Add this entry under upstream.configs in configs/proxy.json"; now stale.
- Docs: `CLAUDE.md` "Config schema (v5)" section, the operator-flow paragraph in
  `cmd/vpntunnel/main.go`'s package doc, and `configs/proxy.example.json`.

## Assumptions

- The scan directory is hardcoded to `filepath.Join(configDir, "tunnels")`, where
  `configDir = filepath.Dir(configPath)`. No new config field. This matches the
  existing `.gitignore` (`/configs/tunnels/*`) and CLAUDE.md convention.
- "Top-level `*.conf` only": no recursion into subdirectories; `.gitkeep`,
  hidden/dotfiles, and any non-`.conf` file are ignored. Case sensitivity of the
  `.conf` suffix follows the host filesystem via `filepath.Glob("*.conf")` /
  suffix check — we match the literal lowercase `.conf` suffix (Mullvad and the
  existing convention always emit lowercase `.conf`).
- A directory that exists but contains zero eligible `.conf` files → startup error
  (same class as today's empty-`configs` error). A directory that is **missing
  entirely** is treated as a startup error too (the operator forgot to create /
  populate it), with a message distinct enough to be actionable. (See Risks for
  the alternative — treat-as-empty — and why we reject it.)
- Broken/unparseable `.conf` files are NOT discovery's concern: discovery only
  globs filenames, it does not parse. `VerifySingleKey` already warn-skips
  unparseable configs, and a config that parses but is malformed for dialing
  surfaces at device-build time. Discovery returning a path that later fails to
  parse must not crash startup — and it won't, because `VerifySingleKey` only
  fails when ALL configs fail to parse, and the device builders are lazy.
- The discovered slice must be **deterministically ordered** (sorted) so that the
  eligible set's `order` slice — and therefore any order-sensitive logging / tests
  — is stable across runs. `filepath.Glob` returns sorted results, but we sort
  explicitly to not depend on that guarantee.
- Discovery returns **absolute** paths already resolved (mirroring
  `NewEligibleSet`'s `filepath.Abs` step), so the contract is consistent end to
  end even though `NewEligibleSet` would re-resolve them harmlessly.

## Tasks

### Task 1: Add `DiscoverConfigs` to the `lazy` package

- **Description:** Add a new exported function
  `func DiscoverConfigs(tunnelsDir string) ([]string, error)` to a new file
  `internal/tunnel/lazy/discover.go`. It lists top-level `*.conf` files in
  `tunnelsDir`, ignoring subdirectories, dotfiles (names beginning with `.`,
  which also excludes `.gitkeep`), and any non-`.conf` entry. It returns the
  matching paths resolved to absolute, sorted ascending by path.

  Placement rationale (CLAUDE.md "package placement follows consumption"):
  discovery is a tunnel concern, sits next to `NewEligibleSet` / `VerifySingleKey`
  which consume `[]string` config paths, and is a peer of the eligible/verify
  logic — not launcher wiring. So it belongs in `internal/tunnel/lazy`, not inline
  in `main.go`. It is not a shared bootstrap layer; it is one cohesive
  business-logic helper for the single concern "where do tunnel configs come from".

  Error semantics:
  - Directory does not exist (`os.IsNotExist` on the `os.ReadDir` error) →
    return a `*publicerror.Error` naming the path, e.g.
    `"config.upstream: tunnels directory <dir> not found; create it and drop your wg-quick .conf files there"`.
  - Other `os.ReadDir` errors (permission, not-a-directory) → plain wrapped error.
  - Directory exists but yields zero `.conf` files → return `(nil, nil)`
    (empty slice, no error). The empty-set error is the responsibility of
    `NewEligibleSet` (so the message stays consistent with the country-filter
    empty case). Do NOT duplicate the empty check here.

  Use `os.ReadDir` (not `filepath.Glob`) so we can cheaply skip directories via
  `entry.IsDir()` and skip dotfiles by name. For each surviving regular entry
  whose name ends in `.conf`, join with `tunnelsDir` and resolve via
  `filepath.Abs`. Sort the result with `sort.Strings` before returning.

- **Acceptance Criteria:**
  - [ ] `internal/tunnel/lazy/discover.go` exists with godoc on `DiscoverConfigs`
        starting with the identifier name and ending with a period, documenting:
        top-level only, dotfiles/`.gitkeep`/subdirs ignored, paths returned
        absolute + sorted, missing-dir → publicerror, empty-but-present → `(nil, nil)`.
  - [ ] New file `discover_test.go` with a single `TestDiscoverConfigs` containing
        subtests (per CLAUDE.md "one `Test*` per function, scenarios as subtests",
        all `t.Parallel()` where no shared mutable state):
        - `"returns sorted absolute paths for top-level .conf files"` — three
          `.conf` files written in non-sorted creation order; assert returned slice
          is sorted, absolute, and contains exactly those three.
        - `"ignores .gitkeep, dotfiles, and non-.conf files"` — dir containing
          `.gitkeep`, `.hidden.conf`, `notes.txt`, `a.conf`; assert only `a.conf`
          returned.
        - `"ignores subdirectories and does not recurse"` — a subdir `sub/` holding
          `nested.conf`; assert `nested.conf` is NOT returned.
        - `"empty but present directory returns nil slice and no error"`.
        - `"missing directory returns a PublicError naming the path"` — assert the
          error is `*publicerror.Error` (use `errors.As`) and `Details()` contains
          the directory path.
  - [ ] `make test` passes (race + vet + gofmt).
  - [ ] No `_`-discarded errors; `os.ReadDir`, `filepath.Abs` errors all checked.

- **Pitfalls & edge cases:**
  - Distinguishing missing-dir from other read errors: only `errors.Is(err, fs.ErrNotExist)`
    (equivalently `os.IsNotExist`) becomes a publicerror; everything else stays a
    plain error so the generic fallback hides path/permission internals.
  - `entry.IsDir()` for a `*.conf` *directory* (someone made a dir named `x.conf`):
    skip it — only regular files count. Symlinks: `os.ReadDir` reports the entry
    type without following; a symlink to a `.conf` will have a non-regular type.
    Decide explicitly — accept regular files only (`entry.Type().IsRegular()`),
    which drops symlinks. Document this; if symlinked configs are ever needed it is
    a separate change. (Mullvad drops plain files, so this is safe today.)
  - Dotfile check must be on the **entry name**, not the full path, or a dotted
    parent directory component would wrongly exclude everything.
  - Sorting must happen on the **final absolute paths** (or equivalently the names
    before joining, since the dir prefix is constant) so ordering is stable.
  - Do NOT parse the `.conf` here — discovery is filename-only. Broken-file
    handling lives downstream (`VerifySingleKey` warn-skip), per locked decision 3.

- **Complexity:** Easy

## Risks

- **Missing-dir = error vs treat-as-empty.** We chose error. An empty/absent
  `tunnels/` dir with `treat-as-empty` would funnel into the same empty-set error
  via `NewEligibleSet` anyway, so a separate publicerror in discovery is mostly
  about message quality. Risk: if any deployment legitimately runs with the dir
  created lazily later, startup-fail is wrong. Mitigation: the host setup
  hand-authors `/opt/vpntunnel/configs/tunnels/` once (CLAUDE.md "Deployment"), so
  the dir always exists in production; failing loud on a missing dir catches a
  genuine misconfiguration. Accept the risk.
- **Silent set drift.** Folder-scan means dropping a stray `.conf` into the dir
  silently enlarges the eligible pool — no longer gated by an explicit list edit.
  Mitigation: the dir is gitignored, 0600-per-file convention, single-key guard
  still runs, and the "tunnel configs discovered" count is logged at startup so an
  unexpected count is visible. Operationally acceptable for a single-operator host.
- **Country-parse drops.** A `.conf` named outside the `mullvad-<cc>` / `<cc>-`
  convention yields `CountryFromID("") == ""`; with a non-empty `allowed_countries`
  it is silently dropped (could surprise an operator who expected it included).
  This is existing `NewEligibleSet` behaviour, unchanged. Covered by an explicit
  test note. Mitigation: the discovered-count log vs eligible-count divergence is
  the operator's signal; consider (future, not this plan) logging the dropped set.
- **Test decoupling assumption.** The plan relies on `config.Load` NOT touching the
  filesystem for tunnels (discovery is in main.go). If a reviewer wants discovery
  folded into `config.Load`, that changes Task 4 substantially. The split is
  intentional (config validation stays pure / filesystem-light) and matches the
  current architecture where `NewEligibleSet`/`VerifySingleKey` already live in
  `lazy`, not `config`.

## Trade-offs

- **Discovery in `lazy` over inline in `main.go`:** chose `lazy.DiscoverConfigs`
  over an inline glob in `main.go`. Per CLAUDE.md "package placement follows
  consumption" and "business logic by concern", discovery is a tunnel-sourcing
  concern that sits alongside `NewEligibleSet`/`VerifySingleKey` and is independently
  testable. Inlining it in the composition root would couple a testable concern to
  launcher wiring. It is one cohesive helper, not a shared bootstrap layer, so this
  does not violate the "no shared startup layer" rule.
- **Empty check stays in `NewEligibleSet`, not duplicated in discovery:** chose to
  let discovery return `(nil, nil)` for an empty-but-present dir and let
  `NewEligibleSet` raise the single, consistent empty-set publicerror. Avoids two
  divergent "no configs" messages and keeps the empty-after-country-filter and
  empty-dir cases funneling through one error path.
- **Missing-dir as publicerror in discovery:** chose to special-case the
  not-exist error for a precise operator message, accepting a small amount of
  os-error branching in discovery, over a generic plain error that the controller
  would mask behind the fallback. The directory's existence is an operator-fixable
  precondition, so a public message is the right call per the project's error
  contract.
- **Reject `upstream.configs` instead of silently ignoring it:** chose an explicit
  probe-rejection publicerror over tolerating a now-dead field. Mirrors the existing
  `config.admin` removal handling; gives operators a clear migration signal instead
  of a silently-ignored field that looks like it still works.
- **`VerifySingleKey` over the discovered (pre-filter) set, not the eligible set:**
  preserves current behaviour and is semantically correct — the single-account
  invariant spans all the operator's configs regardless of which countries are
  enabled this run.
