# Task Breakdown

## Overview

Add a Telegram notifier to `vpntunnel` that sends a message whenever the tunnel
the service is using changes. Two independent triggers:

1. **Streaming supervisor** (`internal/tunnel/lazy/supervisor.go`) — at startup
   (first tunnel pick) and on every successful reconnect. Not rate-limited.
2. **On-demand scheduler** (`internal/tunnel/lazy/scheduler.go`) — when the
   on-demand path switches zone/device. Rate-limited / de-duplicated to avoid
   Telegram spam, because zone switches can be frequent.

After a device is built, the notifier does one best-effort HTTP GET **through the
tunnel dialer** to `https://am.i.mullvad.net/json` to learn the exit IP / city.
On any failure the exit line is omitted; the probe never blocks startup or the
reconnect/request path.

The feature is opt-in via the `VPNTUNNEL_TELEGRAMBOT_DSN` environment variable
(the service reads zero env vars today; systemd injects env through
`EnvironmentFile=/opt/vpntunnel/.env`). Unset/empty → notifier disabled, service
runs normally. Implementation is lightweight: stdlib `*http.Client` posting to the
Bot API `sendMessage` endpoint. The only new `go.mod` dependency is
`github.com/prorochestvo/dsninjector` (v0.0.2, already used across the fleet) for
DSN parsing.

## Package placement decision

New package `internal/notify`.

- It is consumed by **three** call sites: the streaming supervisor, the on-demand
  scheduler (both in `internal/tunnel/lazy`), and the `cmd/vpntunnel/main.go`
  composition root. Per CLAUDE.md "package placement follows consumption", code
  shared by multiple consumers belongs in the shared `internal/` tree — not under
  `cmd/vpntunnel/`.
- `internal/` over `pkg/`: there is no external (out-of-module) importer.
- No import cycle: `internal/notify` imports `internal/tunnel` (for the
  `tunnel.Dialer` type used by the exit-IP probe); `internal/tunnel/lazy` imports
  `internal/notify`. `internal/notify` does **not** import `internal/tunnel/lazy`,
  so the graph stays acyclic.

## Assumptions

- **A present-but-malformed DSN logs a loud WARNING and disables the notifier**
  (warn + disable), it does **not** abort startup. Rationale: the notifier is
  auxiliary telemetry; a DSN typo must never crash-loop the VPN proxy (the actual
  product). The failure is surfaced loudly in the operational log (redacted, never
  the secret), so it is not silent, but egress keeps serving. This mirrors the
  fleet's "Telegram is optional, never fail the job" stance (CI uses `|| true`).
  Unset/empty var also disables the notifier (quietly, at info level).
- No `getMe` identity probe at construction (unlike hive's `NewTBotClient`). We
  only ever send; validating the token would add a network round trip to startup
  for no functional gain. A bad token surfaces as a redacted warning on the first
  failed send.
- Telegram send failures are always non-fatal: log a redacted warning and
  continue.
- The exit-IP probe is best-effort and runs in the notifier's own sender
  goroutine (off the reconnect loop / request path). By the time it runs the
  captured dialer may already be torn down (esp. on-demand); a failed probe simply
  omits the exit line.
- The streaming supervisor's tunnel id is the config **basename without `.conf`**
  (`tunnelIDFromPath`), so the `.conf` filename is `id + ".conf"` and the country
  is `tunnel.CountryFromID(id)`.
- The on-demand scheduler's zone id is the **opaque HMAC id**, so the filename and
  country must be derived from the config **path** (`settleConfigPath`), not the
  zone id: `filepath.Base(configPath)` and
  `tunnel.CountryFromID(strings.TrimSuffix(base, ".conf"))`.
- `am.i.mullvad.net/json` returns `{ip, country, city, mullvad_exit_ip,
  mullvad_exit_ip_hostname}`. For non-Mullvad providers the endpoint still returns
  at least `ip`; `country`/`city` may be empty — handle empties gracefully.
- The netstack dialer resolves hostnames itself (`tnet.DialContext` in
  `internal/tunnel/wireguard/dialer.go:149` does DNS through the tunnel), so the
  probe can dial `am.i.mullvad.net:443` directly via `dialer.DialContext` — no
  pre-resolution through `tunnel.Resolver` is needed.

  ```go
      return errors.New(tokenInURLPattern.ReplaceAllString(err.Error(), "${1}<redacted>"))
  ```

### Task 3: Exit-IP probe through the tunnel dialer

- **Description:** In `internal/notify/probe.go`, add a best-effort probe that
  dials `https://am.i.mullvad.net/json` **through** a `tunnel.Dialer` and decodes
  the exit info.
  - `type exitInfo struct { IP, Country, City string }` (unexported).
  - `func probeExitIP(ctx context.Context, d tunnel.Dialer, endpoint string) (exitInfo, error)`:
    build a one-shot `*http.Client` whose `Transport` has
    `DialContext: d.DialContext` and `Proxy: nil`, `Timeout` bounded (~5s); GET
    `endpoint`; require 200; JSON-decode `{ip, country, city}` (extra fields
    ignored). `endpoint` is a parameter (default `https://am.i.mullvad.net/json`)
    so tests can point it at an `httptest` server.
  - Bound the probe with a derived `context.WithTimeout` (~5s) even when the caller
    ctx has no deadline.
- **Acceptance Criteria:**
  - [ ] `TestProbeExitIP` subtests, all using a fake `tunnel.Dialer` whose
        `DialContext` dials an `httptest.Server`:
        - happy path: server returns `{"ip":"185.213.155.10","country":"Sweden","city":"Stockholm"}`
          → `exitInfo{IP:"185.213.155.10", City:"Stockholm", ...}`.
        - dialer returns an error → non-nil error, zero `exitInfo`.
        - server returns 500 → error.
        - server hangs past the timeout → error (context deadline).
  - [ ] Fake dialer has `var _ tunnel.Dialer = (*fakeDialer)(nil)` assertion.
  - [ ] The probe never panics on a `nil` dialer — caller guards, but assert a
        `nil`-dialer guard returns an error rather than dereferencing.
- **Pitfalls:** The `http.Transport` must set `Proxy: nil` (or a func returning
  `nil,nil`) so the probe never routes through any process-wide proxy — it must go
  through the tunnel dialer only. Do **not** reuse a shared transport across
  probes: each probe binds to a specific (possibly short-lived) dialer. Close the
  response body. Cap the decoded body (`io.LimitReader`, e.g. 64 KiB) so a rogue
  endpoint can't stream unbounded. Never log `.conf` contents; only IP/country/city
  from the response and the basename may surface.
- **Complexity:** Medium
- **Code Example:**
  ```go
  func probeExitIP(ctx context.Context, d tunnel.Dialer, endpoint string) (exitInfo, error) {
      if d == nil {
          return exitInfo{}, errors.New("notify: nil dialer")
      }
      ctx, cancel := context.WithTimeout(ctx, probeTimeout)
      defer cancel()
      c := &http.Client{Transport: &http.Transport{
          Proxy:       func(*http.Request) (*url.URL, error) { return nil, nil },
          DialContext: d.DialContext,
      }}
      req, err := http.NewRequestWithContext(ctx, http.MethodGet, endpoint, nil)
      // ... do, check 200, json.NewDecoder(io.LimitReader(resp.Body, 64<<10)).Decode(&raw)
  }
  ```

### Task 4: Message formatting + HTML escaping

- **Description:** In `internal/notify/message.go`, build the HTML message body.
  - `func formatMessage(title, country string, exit *exitInfo, filename string) string`

    ```
    <pre>{filename}</pre>     (omitted when filename == "")
    ```

    `country != ""` → just `country`. When neither → omit the details line.
  - HTML-escape **every** interpolated value (`title`, `country`, `ip`, `city`,
    `filename`) with `html.EscapeString`. The literal `#VPNTUNNEL` prefix and the
    `<pre>` tags are not escaped.
- **Acceptance Criteria:**
  - [ ] `TestFormatMessage` subtests: full (title+country+exit+filename); no exit
        (details == country only); no country and no exit (no details line);
        empty filename (no `<pre>`); a `city` / `filename` containing `<`, `&`,
        `"` → escaped in output; a crafted `title` with `<b>` → escaped.
  - [ ] Output uses `\n` separators and contains `#VPNTUNNEL ` exactly once.
- **Pitfalls:** Escape the value, not the tag — `<pre>` must remain literal so

  middle line renders as an ugly gap). Filename is operator-supplied and safe, but

- **Complexity:** Easy

### Task 6: `TelegramNotifier` — assemble, async sender, dedup/rate-limit, Close

- **Description:** In `internal/notify/telegram.go`, the concrete `Notifier`.
  - `func NewTelegram(dsn string, opLog *slog.Logger) (*TelegramNotifier, error)`:
    parse the DSN (Task 2), store `adminChatID`, `token`, `apiBase`, `probeURL`,

    `notifier enabled` with `token_len` only (never the token/DSN/chat id).
  - `Notify(ctx, ev Event)` (implements `Notifier`): does the **cheap** work only
    — for `SourceOnDemand`, apply the dedup/rate-limit check under a mutex
    (see below) and drop if suppressed; then non-blocking enqueue the event into a
    buffered channel (`select { case ch <- job: default: warn "notify queue full, dropping" }`).
    **Never blocks** the caller. The probe + format + send happen in the sender
    goroutine, not here.
  - Sender goroutine: `for job := range ch { … }` — probe exit IP (Task 3, using
    the notifier's own background ctx so a cancelled request ctx doesn't kill the
    send), format (Task 4), send (Task 5); log any failure as a redacted warning.
  - **Dedup / rate-limit (on-demand only):** state `mu`, `lastOnDemandFilename`,
    `lastOnDemandAt`. Suppress when `ev.Filename == lastOnDemandFilename &&
    now.Sub(lastOnDemandAt) < onDemandDedupWindow` (same tunnel repeated) OR when
    `now.Sub(lastOnDemandAt) < onDemandMinInterval` (global floor across zones).
    Otherwise update state and enqueue. `SourceStreaming` bypasses this entirely.
    Constants (`onDemandDedupWindow` e.g. 5m, `onDemandMinInterval` e.g. 20s,
    `probeTimeout` 5s, channel buffer e.g. 32) live in the package as consts,
    matching the built-in-constants pattern used by `internal/asyncjob`.
  - `Close()`: cancel the notifier's internal ctx (aborts any in-flight probe/send
    fast), close the channel, and wait for the sender goroutine's `done` channel —
    bounded because all pending ops fail fast on the cancelled ctx. Idempotent via
    `sync.Once`.
  - `var _ Notifier = (*TelegramNotifier)(nil)`.
  - Inject a `Clock`/`now func() time.Time` seam (or reuse the existing
    `lazy.Clock` pattern via a small local interface) so the dedup window is
    testable without sleeps.
- **Acceptance Criteria:**
  - [ ] `TestTelegramNotifier_Notify` subtests (sender wired to an `httptest`
        telegram server and a fake dialer, injected `now`):
        - streaming event → one send; a second identical streaming event → a
          second send (streaming never deduped).
        - on-demand event, then same-filename on-demand event within the window →
          exactly one send (dedup).
        - on-demand event, then different-filename within `onDemandMinInterval` →
          one send (floor); after advancing `now` past the floor → the second
          sends.
        - probe fails (fake dialer errors) → message still sent, without the exit
          line.
        - telegram server returns 500 → no panic, warning logged, `Notify`/sender
          survive.
  - [ ] `TestTelegramNotifier_Close`: after `Close`, the sender goroutine has
        exited (assert via the `done` channel / a `WaitGroup`); a second `Close`
        is a no-op; `Notify` after `Close` does not panic (enqueue hits the
        closed-channel guard or the `default` drop).
  - [ ] `-race` clean (dedup state under `mu`; sender is the only channel reader).
  - [ ] Startup log line asserts `token_len` present and token/DSN/chat-id absent.
- **Pitfalls:** Enqueue must be non-blocking — a full buffer drops with a warning,
  it must never stall the reconnect loop or a proxy request. Use the notifier's
  **own** background context for probe/send, not the per-call `ctx` (a request ctx
  is cancelled the instant the request returns, which would kill the async send).
  Update dedup state on **enqueue**, not on send success (dedup is best-effort and
  must not depend on the async result). Guard against send-after-Close on the
  channel (recover or a closed flag under `mu`). Do not leak the sender goroutine.
- **Complexity:** Hard

## Risks

- **Probe races a torn-down device.** The captured `Dialer` may be closed before
  the async sender probes it (esp. on-demand after grace/idle). Mitigation:
  best-effort — a failed probe omits the exit line; never fatal. Accepted.
- **Telegram outage / slow API stalls the sender.** A single sender goroutine
  processing slow sends could back the queue up. Mitigation: bounded per-op
  timeouts + non-blocking enqueue that drops on a full buffer. The hot paths
  (reconnect loop, proxy request) are never blocked.
- **Secret leakage in logs/errors.** The token lives in the sendMessage URL path
  and in probe/send `*url.Error`s. Mitigation: `redactToken` on every returned/
  logged error; startup logs only `token_len`; unit tests assert no secret in
  error text. This is the highest-severity risk — reviewer Lens B must verify it.
- **Bad DSN silently drops notifications.** A malformed DSN warn-disables the
  notifier (per the Assumptions decision) — egress is unaffected, but the operator
  may believe notifications work when they don't. Mitigation: the disable is logged
  at WARN with a redacted reason, so it is visible in `journalctl`; not silent.
  Availability of the proxy is prioritized over loud failure of an auxiliary
  feature.
- **`go.mod` surface.** Adding `dsninjector` is low-risk (already fleet-vetted at
  v0.0.2) but is a new third-party dependency in a security-sensitive binary. No
  transitive CGO; keep `CGO_ENABLED=0` builds green.

## Trade-offs

- **`internal/notify` (shared) over `cmd/vpntunnel/`:** chose shared because there
  are genuinely three consumers (supervisor, scheduler, main). Co-locating under
  `cmd/vpntunnel/` would force `internal/tunnel/lazy` to import from `cmd/`, which
  is backwards. This is real cross-consumer code, not aspirational reuse.
- **Lightweight stdlib client over `OvyFlash/telegram-bot-api`:** we only ever
  send one message and never poll, so the full bot library (long-polling, command
  routing, update parsing) is dead weight. Chose a ~30-line `sendMessage` over a
  heavy dependency. Cost: we reimplement token redaction and DSN parsing — both
  small and mirrored from hive.
- **Single `Notify(ctx, Event)` method with a `Source` field over two methods:**
  keeps the interface minimal and lets the notifier own the dedup policy keyed on
  `Source`, rather than leaking "rate-limited vs not" into two call-site-specific
  methods. Cost: the caller sets `Source`, a tiny coupling.
- **Dedup lives in the notifier, not the scheduler:** single source of truth for
  the anti-spam policy, independently unit-testable without spinning up the whole
  scheduler. Cost: the scheduler calls `Notify` on every switch and relies on the
  notifier to drop — asserted in tests.
- **Async sender goroutine + bounded queue over per-event goroutines:** gives a
  clean `Close`/drain story for `main`'s ordered shutdown and naturally serializes
  sends (friendlier to Telegram rate limits). Cost: one long-lived goroutine and a
  small buffer to manage; a full buffer drops events (acceptable for
  notifications).
- **Warn + disable on present-but-malformed DSN over fatal:** the notifier is
  auxiliary; a DSN typo must never crash-loop the VPN proxy. The misconfiguration
  is surfaced as a redacted WARN (visible in `journalctl`), not silently swallowed,
  but egress keeps serving. Availability of the core product wins over loud failure
  of a cosmetic feature. Cost: an operator could miss the WARN and believe
  notifications are live when they are disabled.
