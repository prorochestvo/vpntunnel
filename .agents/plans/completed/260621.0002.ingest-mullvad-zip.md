# Task Breakdown

## Overview

Add a second assembly mode to the existing `cmd/generatevpnconfig/` interactive
operator CLI: **zip-ingest**. Instead of typing every wg-quick field by hand, the
operator feeds a Mullvad-downloaded `.zip` of wg-quick `.conf` files, and the tool
injects the locally-generated private key into every `[Interface]` block, writing one
`.conf` per server into `configs/tunnels/`. This lets one local key + one assigned
Address fan out across many Mullvad servers (the configs differ only in the `[Peer]`
block) without burning Mullvad's 5-device limit and without the private key ever
leaving the machine.

The current tool (`cmd/generatevpnconfig/main.go`) already:

- guards on TTY, generates the keypair via `wgtypes.GeneratePrivateKey()`, prints the
  public key + Mullvad instructions,
- prompts field-by-field with validation (`promptRequired`, `promptOptional`,
  `promptAddress`),
- writes atomically at 0600 (`writeAtomicConf`), resolves/guards the output path
  (`resolveOutputPath`), validates names (`validateName`),
- round-trips the written file through `wgconf.Parse` and prints a `proxy.json` snippet.

This feature reuses all of those helpers. The new code is: a mode-selection prompt
right after keygen, a zip-path prompt, a zip-ingest function, and a per-`[Interface]`
PrivateKey line swapper. The keypair is generated **once per run** and the same run
either does the manual flow or the zip flow, so the private key lives only in memory
for the run.

**Approach for mode selection (chosen):** interactive numbered choice right after
keygen — `[1] manual field entry  [2] a downloaded Mullvad zip` — rather than a `-zip`
flag. Justification in Trade-offs. The zip *path* is still prompted interactively in
either case (the zip does not exist until after the operator adds the just-printed
pubkey to Mullvad and downloads configs for it).

### Verified codebase facts (do not re-derive)

- `wgconf.Parse(path string, opLog *slog.Logger) (*ParsedConfig, error)` — takes a
  **file path**, not a reader. So round-trip validation must write the file first, then
  Parse it — identical to the existing manual flow at `main.go:153`.
- `ParsedConfig.Interface.Addresses []netip.Prefix` is exported → the Address-consistency
  check (Task 7) compares parsed `Interface.Addresses` across produced files.
- `ParsedConfig.Peer.PresharedKey string` is exported and the parser reads `presharedkey`
  in the `[Peer]` block (`wgconf.go:265`) → PresharedKey survives the round-trip and the
  injector must NOT touch it.
- The parser rejects multi-peer (`wgconf.go:176`) and errors loudly on missing
  PrivateKey / Address / PublicKey / Endpoint (`wgconf.go:284-295`) → round-trip
  validation genuinely catches a malformed injected file.
- `warnAndSkipKeys` includes `listenport`, `table`, etc. (`wgconf.go:75`). Mullvad confs
  carrying those WARN-and-skip during round-trip rather than failing. Pass the same
  `slog.New(slog.NewTextHandler(io.Discard, nil))` discard logger used at `main.go:153`
  so warnings don't chatter to stderr.
- `archive/zip` is stdlib → ZERO new deps (CLAUDE.md dependency table unchanged).
- Existing helpers to reuse verbatim: `writeAtomicConf(dir, finalPath, body string)`,
  `validateName(name string)`, and the `resolveOutputPath` overwrite/escape pattern
  (`main.go:372-395`).
- Test layout: `cmd/generatevpnconfig/main_test.go` already has one `Test*` per method
  with subtests (`TestRun`, `TestValidateName`, `TestResolveOutputPath`,
  `TestWriteAtomicConf`, …). New tests follow the same shape.
- Makefile target `generate-vpn-config` runs `CGO_ENABLED=0 go run ./cmd/generatevpnconfig`.
  With the interactive-choice approach the target needs no new flag plumbing — only its
  comment block is updated.

## Assumptions

- The operator runs the tool, adds the printed pubkey to Mullvad, generates configs
  **for that key**, downloads the zip, and supplies its path — all in one TTY session.
  The tool cannot verify key↔Address matching offline (the Mullvad REST client was deleted
  in v3), so we document the constraint and emit a loud warning; we do not attempt a
  network check.
- Mullvad zips contain one wg-quick `.conf` per server at the archive root (possibly with
  a containing directory). We derive names from `filepath.Base` of the entry and never
  trust the entry's directory path (zip-slip avoidance).
- Each `.conf` is well under 1 KB. Caps of ≤ 64 entries and ≤ 8 KB decompressed per entry
  are generous headroom and bound zip-bomb exposure.
- An operator may legitimately re-run to refresh configs; `-force` semantics apply
  per-output-file exactly as today.
- A zip may contain non-`.conf` entries (READMEs, directory entries); those are skipped.
  A zip with zero `.conf` entries is an error.
- "Verbatim preserve" means byte-for-byte except the single `PrivateKey =` value line in
  `[Interface]`. We do NOT re-serialize from `ParsedConfig` (that would drop DNS / PSK /
  multi-address / unknown fields Mullvad included). The parse is validation-only.

## Tasks

### Task 1: Add `injectPrivateKey` — swap the `[Interface]` PrivateKey value in-place

- **Description:** New unexported function in `cmd/generatevpnconfig/main.go`:
  `injectPrivateKey(confBody, privateKey string) (string, error)`. Operate
  line-by-line on the verbatim file content. Track which section we are in by matching
  section headers case-insensitively (`[Interface]`, `[Peer]` — trim then compare with
  `strings.EqualFold`). While inside `[Interface]`, find the first line whose key
  (text before `=`, trimmed, lowered) equals `privatekey` and replace the **value**
  with `privateKey`, preserving the rest of the file unchanged. Emit exactly one
  injected line. If no `PrivateKey` line exists in `[Interface]`, insert
  `PrivateKey = <key>` as the first line immediately after the `[Interface]` header.
  Never touch `PresharedKey` (it lives in `[Peer]`). Preserve original line endings as
  best-effort: operate on the body split by `\n`, re-join with `\n` (Mullvad confs are
  LF; document this). Return an error if there is no `[Interface]` section at all.
- **Acceptance Criteria:**
   - [ ] `TestInjectPrivateKey` exists with subtests:
     - [ ] existing `PrivateKey` line in `[Interface]` → value replaced, all other lines
       byte-identical (assert full output equality against an expected string).
     - [ ] case-insensitive key match: `privatekey =` / `PRIVATEKEY=` both replaced.
     - [ ] no `PrivateKey` line → `PrivateKey = <key>` inserted as first line after the
       `[Interface]` header, header and following lines preserved.
     - [ ] `PresharedKey` in `[Peer]` is never modified, even though it contains the
       substring "Key" — assert the PSK line is byte-identical in output.
     - [ ] a `PrivateKey`-looking line that appears in `[Peer]` (pathological) is NOT
       touched; only the `[Interface]` one is.
     - [ ] missing `[Interface]` section → error.
   - [ ] No `_`-discarded errors; godoc on the function.
- **Pitfalls & edge cases:**
   - Matching the key must be on the part **before** the first `=`, not a substring scan —
     otherwise `PresharedKey` (`...Key`) or a comment could false-match. Compare the lowered
     trimmed left-hand side for exact `privatekey`.
   - A header like `[Interface]` may have trailing inline comment or whitespace; trim and
     compare. Do not lowercase the whole header blindly — use `strings.EqualFold` on the
     trimmed token.
   - Only replace the **first** `PrivateKey` in `[Interface]`; once replaced, stop matching
     so a duplicate (malformed) line isn't double-swapped (the round-trip will still catch
     genuinely malformed input).
   - Preserve blank lines and comment lines exactly — they are part of "verbatim".
- **Complexity:** Medium
- **Code Example:**
  ```go
  // injectPrivateKey returns confBody with the [Interface] PrivateKey value
  // replaced by privateKey. If [Interface] has no PrivateKey line, one is
  // inserted directly after the [Interface] header. PresharedKey (in [Peer]) is
  // never touched. The rest of the body is preserved byte-for-byte. It returns an
  // error if confBody has no [Interface] section.
  func injectPrivateKey(confBody, privateKey string) (string, error) {
      lines := strings.Split(confBody, "\n")
      inInterface := false
      seenInterface := false
      injected := false
      ifaceHeaderIdx := -1
      for i, raw := range lines {
          trimmed := strings.TrimSpace(raw)
          if strings.HasPrefix(trimmed, "[") {
              inInterface = strings.EqualFold(trimmed, "[Interface]")
              if inInterface {
                  seenInterface = true
                  ifaceHeaderIdx = i
              }
              continue
          }
          if inInterface && !injected {
              if eq := strings.IndexByte(raw, '='); eq >= 0 {
                  key := strings.ToLower(strings.TrimSpace(raw[:eq]))
                  if key == "privatekey" {
                      lines[i] = "PrivateKey = " + privateKey
                      injected = true
                  }
              }
          }
      }
      if !seenInterface {
          return "", errors.New("conf has no [Interface] section")
      }
      if !injected {
          insert := "PrivateKey = " + privateKey
          lines = append(lines[:ifaceHeaderIdx+1],
              append([]string{insert}, lines[ifaceHeaderIdx+1:]...)...)
      }
      return strings.Join(lines, "\n"), nil
  }
  ```

### Task 2: Add `readZipEntries` — extract `.conf` entries in memory with caps

- **Description:** New unexported function:
  `readZipEntries(zipPath string) ([]zipConf, error)` where
  `type zipConf struct { name string; body string }` (`name` = sanitized basename
  without `.conf`; `body` = full file content). Open the zip via
  `zip.OpenReader(zipPath)` (defer Close). Iterate `r.File`; for each entry: skip
  directory entries (`f.FileInfo().IsDir()`); compute `base := filepath.Base(f.Name)`;
  skip entries whose extension is not `.conf` (case-insensitive); strip the `.conf`
  suffix to get the candidate name and run it through `validateName` (reject `..`,
  separators, leading dot, etc.); enforce caps (≤ 64 entries total, ≤ 8 KB per entry
  decompressed); read the entry into memory with an `io.LimitReader` bounded to the
  per-entry cap + 1 (so an over-cap entry is detected, not silently truncated). Collect
  into the slice. Return an error if zero `.conf` entries were found.
- **Acceptance Criteria:**
   - [ ] `TestReadZipEntries` with subtests (build the test zips in-memory with
     `archive/zip` into a `bytes.Buffer`, write to a `t.TempDir()` file):
     - [ ] two `.conf` entries → both returned with correct sanitized names + bodies.
     - [ ] entry at a nested path (`foo/bar/se.conf`) → name derived from basename `se`,
       never `foo/bar`.
     - [ ] non-`.conf` entries (`README.txt`, a directory) → skipped.
     - [ ] zip with zero `.conf` entries → error.
     - [ ] entry name that fails `validateName` (e.g. `../evil.conf`, `.hidden.conf`) →
       error (or skipped-with-error — pick reject-loudly and assert the error).
     - [ ] entry exceeding the per-entry size cap → error mentioning the cap.
     - [ ] more than 64 entries → error mentioning the entry-count cap.
   - [ ] No new module dependencies (`archive/zip`, `io`, `bytes` are stdlib).
   - [ ] godoc on `readZipEntries` and `zipConf`.
- **Pitfalls & edge cases:**
   - `filepath.Base("../evil.conf")` is `evil.conf`, which sanitizes fine — but
     `filepath.Base` on a Windows-style `..\evil.conf` on Linux is the whole string;
     `validateName` rejects backslashes, so that path is covered. Still, derive the name
     from `filepath.Base` AND pass through `validateName` (defense in depth), then build
     the output path with `filepath.Join(cfg.dir, name+".conf")` only.
   - `zip.OpenReader` must be closed; use `defer func(){ _ = r.Close() }()` (Close in defer
     is an allowed `_` exception per CLAUDE.md).
   - `LimitReader` to cap+1 then check the read length > cap to distinguish "exactly cap"
     from "over cap".
   - Decompressed-size cap, not compressed-size — a zip bomb inflates after decompression.
   - Case-insensitive `.conf` match: `strings.EqualFold(filepath.Ext(base), ".conf")`.
- **Complexity:** Medium

### Task 3: Add `ingestZip` — orchestrate inject + validate + write for all entries

- **Description:** New unexported function:
  `ingestZip(cfg runConfig, key wgtypes.Key, zipPath string) ([]string, error)` returning
  the list of written output names (for the proxy.json snippet). Steps: call
  `readZipEntries(zipPath)`; for each `zipConf`: resolve the output path via the same
  logic as `resolveOutputPath` (reuse it — pass `cfg` and `entry.name`) so the dir is
  created, the escape check runs, and `-force` overwrite policy is honored per file; call
  `injectPrivateKey(entry.body, key.String())`; `writeAtomicConf(cfg.dir, outPath, body)`;
  round-trip `wgconf.Parse(outPath, discardLogger)` and fail loudly for that file if it
  errors. Accumulate produced names. After all files: run the Address-consistency check
  (Task 7). Return the names. Fail the whole run on the first hard error (a half-written
  batch is acceptable — the operator re-runs; document this), but make the error message
  name the offending file.
- **Acceptance Criteria:**
   - [ ] `TestIngestZip` with subtests (in-memory zip → temp dir):
     - [ ] happy path: 3 server confs → 3 files written at 0600 in `cfg.dir`, each
       containing the injected private key in `[Interface]`, each round-trip-parses.
     - [ ] each written file's `[Peer]` block (PublicKey, Endpoint, PresharedKey, DNS,
       extra Mullvad fields) is preserved verbatim from the source entry.
     - [ ] an existing output file with `force=false` → error, no overwrite; with
       `force=true` → overwritten.
     - [ ] a deliberately broken entry (e.g. missing `[Peer]`) → error naming that file.
     - [ ] returned name list matches the `.conf` basenames (without extension).
   - [ ] The private key string never appears in any returned error or printed output
     (only inside the written file) — assert no error text contains `key.String()`.
   - [ ] godoc; no `_`-discarded errors.
- **Pitfalls & edge cases:**
   - `resolveOutputPath` calls `os.MkdirAll` every iteration — harmless (idempotent) but
     note it; do not refactor it out of the loop unless trivially clean.
   - Round-trip parse must use the discard logger, not `slog.Default()`, to avoid WARN
     spam from Mullvad's `ListenPort` etc.
   - Partial-batch failure: files written before the failing entry remain. State this in
     the error so the operator knows to inspect/clean `configs/tunnels/`. Do not attempt
     transactional rollback across files — out of scope and fragile.
   - The escape check (`filepath.Dir(out) == filepath.Clean(cfg.dir)`) is the same
     defense-in-depth as `resolveOutputPath`; reusing that function gives it for free.
- **Complexity:** Medium

## Risks

- **Key↔Address mismatch is unverifiable offline.** If the operator supplies a zip
  generated for a *different* key, the tool will happily inject and write valid-looking
  configs that fail to handshake at runtime. Mitigation: the single-run design + the
  explicit warning (Task 5) + the Address-consistency warning (Task 7). We accept that the
  ultimate correctness check is a successful handshake, surfaced by
  `/v1/admin/health`. Document this clearly; do not pretend the tool guarantees a match.
- **Verbatim-preserve fragility.** Re-joining on `\n` normalizes line endings; a CRLF
  Mullvad zip would lose `\r`. Mullvad ships LF, and the round-trip parser is
  whitespace-tolerant, so functionally safe — but assert the LF assumption in a test and
  document it. If a CRLF source ever appears, the parse still passes (parser trims), so the
  blast radius is cosmetic.
- **Zip bomb / hostile archive.** Mitigated by per-entry decompressed-size cap (≤ 8 KB),
  entry-count cap (≤ 64), in-memory read (no extraction by entry path), and output paths
  built solely from `filepath.Join(cfg.dir, sanitizedName+".conf")` with the same escape
  check as `resolveOutputPath`. Zip-slip is structurally impossible because we never use the
  entry's path.
- **Partial-batch write on mid-loop failure.** Files written before a failing entry remain
  on disk. Accepted (operator re-runs; `-force` overwrites). The error names the failing
  file so the operator can act. Transactional all-or-nothing across files is out of scope.
- **PrivateKey leak via injector bug.** The whole feature's reason to exist is keeping the
  key local. A bug in `injectPrivateKey` that mis-targets a line, or an error message that
  interpolates the body, could leak it. Mitigation: Task 1/3 tests assert the key only
  appears inside written files, never in printed/error output; the key-matching is on the
  left-hand-side token, not a substring scan.

## Trade-offs

- **Interactive mode prompt over a `-zip` flag.** Chosen the numbered prompt
  (`[1] manual  [2] zip`) immediately after keygen. *Why:* the zip flow's path prompt is
  inherently interactive (the zip doesn't exist until after the operator adds the printed
  pubkey to Mullvad), so a flag buys nothing — the operator is already at the terminal
  answering prompts. A flag would also add a CLI surface and a Makefile target to plumb
  through, for zero ergonomic gain. The default (empty input → manual) preserves existing
  muscle memory and keeps the manual flow's behavior byte-identical. Rejected: `-zip` flag.
- **Verbatim line-swap over parse-and-re-serialize.** Chosen to edit only the single
  `PrivateKey` value line and preserve everything else byte-for-byte. *Why:* re-serializing
  from `ParsedConfig` would silently drop anything the parser doesn't model
  (PresharedKey is modeled, but DNS formatting, multi-address ordering, comments, and any
  future Mullvad field are not guaranteed to round-trip identically). The point of ingest is
  to *trust* Mullvad's config and inject only our secret. The parser is used purely as a
  post-write validator. Rejected: build the body from `buildConfBody`-style assembly.
- **Per-file `-force` reuse over a batch confirm.** Chosen to honor existing `-force`
  semantics per output file via `resolveOutputPath`. *Why:* consistency with the manual
  flow and zero new surface. Rejected: a separate "overwrite all? [y/N]" batch prompt —
  more code, divergent from the documented `-force` contract.
- **Caps as constants over configurable limits.** Chosen hard-coded ≤ 64 entries / ≤ 8 KB
  per entry. *Why:* these configs are <1 KB and a Mullvad all-servers zip is well under 64
  entries; exposing knobs invites misconfiguration and adds flags for a threat (zip bomb)
  that a fixed generous cap fully covers. Rejected: configurable caps.
