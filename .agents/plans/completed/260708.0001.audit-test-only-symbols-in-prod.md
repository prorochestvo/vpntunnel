# Task 001 — Audit test-only symbols in production code

## Mission

Find every symbol that lives in a production (`*.go`, non-`_test.go`) file but whose
**only compile-time consumer is a test**, and for each decide: relocate it into
`_test.go`, replace the bespoke test seam with a production interface, or keep it
(because production reads it). This file is the finalized, ordered refactor plan.
Implementation is out of scope — a later `gocode-engineer` pass executes it.

## The criterion — do not blur it

Placement is decided by **compile-time consumption, not intent** (CLAUDE.md → Code
Organization Principles → *"Test-only code lives in `_test.go`, never in a production
file"*):

- Only consumer is a `_test.go` file → test scaffolding → **must** live in `_test.go`.
- Read by production code → **stays** in the production file even if only tests ever set
  it (moving it breaks `go build`). The **setter/constructor moves**; the
  **read-by-prod field/type stays**. Split on exactly that line.

## Seed case and counter-example (from the survey trigger)

Seed: `cmd/vpntunnel/main.go` ships test scaffolding in the binary — the functional-option
constructors `withSupervisorBuilder`, `withSchedulerBuilder`, `withShutdownCtx` are called
**only** from `cmd/vpntunnel/main_test.go` (9 call sites each), yet are defined in `main.go`.

Correct counter-example (do **not** touch): `runOpt`, `runOptions` and its fields
(`supervisorBuilder`, `schedulerBuilder`, `shutdownCtx`) legitimately **stay** in `main.go`
because production `runWithOpts` reads them — `ro.shutdownCtx` at `main.go:289`,
`ro.supervisorBuilder` at `main.go:348`, `ro.schedulerBuilder` at `main.go:369`; the builder
fields nil-default to `DefaultDeviceBuilder`. The `run()` wrapper (`main.go:189`) is the
production entry `main()` calls at `main.go:181`; it hands tests the `runWithOpts(..., opts...)`
seam but is itself production. This is the nil-defaulted-seam split the criterion prescribes.

## Interface-ize evaluation (required) — recommended for ZERO cases

The requester specifically wanted bespoke test seams dropped in favor of production
interfaces where it helps. It does not help here; every actionable case is a clean
relocation. Per-case reasoning:

- **`main.go` trio** — the injection seam is already `lazy.DeviceBuilderFn` (a production
  func type the composition root reads) plus a nil-defaulted `context.Context` field. There
  is no bespoke test-only *type* to eliminate — the `with*` funcs are three-line writers of
  existing production fields. Interface-izing would mean either forking the composition-root
  wiring into the test or threading a new interface through `runWithOpts`, both of which
  violate the *composition-root-stays-inlined-per-binary* invariant (CLAUDE.md → Code
  Organization Principles) and the *do-not-fork-the-wiring* rule that keeps the smoke test on
  the real path. Relocate the setters; keep the fields.
- **`httpserver.StartOn`** — there is no production seam at all: prod `Start()` uses
  `ListenAndServe`, nothing reads `StartOn`. Nothing to interface-ize; it is pure scaffolding
  shipped in the binary. Relocate.
- **`lazy.setRNG`** — the seam is a same-package field assignment of a concrete `*mrand.Rand`.
  An interface around PRNG injection would be pure ceremony with zero production benefit.
  Relocate.
- **`Clock` fields (both)** — already the correct end state: `Clock` interface + production
  `realClock`/`NewRealClock` in `clock.go`, `fakeClock` already in `_test.go` with its
  `var _ Clock = &fakeClock{}` assertion. This is the template the trio would only badly
  imitate. Nothing to do.

Conclusion: **relocation for all five actionable symbols; no interface introduced.**

## Overview

Move five test-only symbols out of production `.go` files into `_test.go` files in their own
packages, verbatim, adjusting only imports. No production behavior changes, no signatures
change, no interfaces added. The read-by-production fields/types the setters target stay
exactly where they are. This is a mechanical hygiene refactor (`refactor:` commits) that
shrinks the shipped binary's reachable surface and enforces the `_test.go` boundary.

## Assumptions

- All three white-box moves are legal same-directory relocations: `main_test.go` is
  `package main`, `eligible_test.go` is `package lazy`, and the `httpserver` test binary
  compiles both black-box (`httpserver_test`) and white-box (`httpserver`) `_test.go` files
  together, so an exported method defined in a white-box `_test.go` is visible to the existing
  black-box `server_test.go`.
- Call-site counts are current: 9× each for the trio (`main_test.go`), 5× for
  `httpserver.StartOn` (`server_test.go:88,131,160,196,242`), 4× for `setRNG`
  (`eligible_test.go:320,335,346,365`). No production caller exists for any of the five.
- No godoc/CLAUDE.md doc references these symbols by their production file location such that
  moving them creates a stale cross-reference (verified: references are prose, not code).

## Tasks

### Task 1 — Relocate the three `main.go` func-option constructors into `main_test.go`

**Description.** Move the block `cmd/vpntunnel/main.go:76-92` — the godoc + body of
`withSupervisorBuilder`, `withSchedulerBuilder`, `withShutdownCtx` — verbatim into
`cmd/vpntunnel/main_test.go` (`package main`, white-box, so it can still write the unexported
`runOptions` fields). Leave in `main.go`: the `runOpt` type (`:58`), the `runOptions` struct
and all three fields (`:62-74`), and the `runWithOpts` reads (`:289-290`, `:348`, `:369`) — the
production build references every one of them.

**Acceptance Criteria.**
- `withSupervisorBuilder`, `withSchedulerBuilder`, `withShutdownCtx` no longer appear in any
  non-`_test.go` file: `grep -rn --include='*.go' 'func with\(Supervisor\|Scheduler\|Shutdown' cmd/vpntunnel/` matches only `main_test.go`.
- `runOpt`, `runOptions`, and the three fields remain in `main.go`.
- `make test` and `make lint` pass; `CGO_ENABLED=0 go build -o ./build/vpntunnel ./cmd/vpntunnel` succeeds.

**Pitfalls.**
- Do **not** drag the `runOptions` fields or `runOpt` type along — they are production-read;
  moving them breaks `go build`. Move only the three `func with*`.
- `main.go` keeps its `context` import (the `shutdownCtx context.Context` field still uses it);
  `main_test.go` already imports `context`, `net`, `lazy`, `slog` — no import churn expected.
- Keep the funcs as helpers in `main_test.go` (do not inline the field-sets into 9 call sites);
  verbatim relocation preserves the existing call sites unchanged.

**Complexity.** Low.

### Task 2 — Relocate `httpserver.StartOn` into a white-box `_test.go`

**Description.** Move `(*Server).StartOn` (`internal/gateway/httpserver/server.go:82-92`,
godoc included) verbatim into a **new white-box** test file in the same directory —
`package httpserver` (e.g. `starton_test.go`) — carrying the `net` import with it. Nothing
stays in production: prod `Start()` (`server.go:74`) uses `ListenAndServe` and never calls
`StartOn`. The existing `server_test.go` is black-box (`package httpserver_test`); the method
touches unexported fields (`s.http`, `s.log`), so it must land in a white-box file, not in the
black-box one.

**Acceptance Criteria.**
- `StartOn` is defined only in a `_test.go` under `internal/gateway/httpserver/`:
  `grep -rn 'func (s \*Server) StartOn' internal/gateway/httpserver/` matches a `_test.go` file.
- `internal/gateway/httpserver/server.go` no longer imports `net` (it was used solely by `StartOn`).
- The 5 black-box call sites in `server_test.go` still compile and pass unchanged.
- `make test` and `make lint` pass; sanity `go build` succeeds.

**Pitfalls.**
- The `net` import in `server.go` is used **only** by `StartOn` (verified). After the move,
  remove it from `server.go` or `go vet`/gofmt will fail on an unused import; add it to the new
  white-box `_test.go`.
- The new file must be `package httpserver` (white-box), not `httpserver_test` — the method
  reads unexported fields. This is a legitimate white-box relocation, not an `export_test.go`
  park; the method is exported and reachable from the black-box test because both compile into
  one test binary.
- Do not confuse with `router.StartOn`, which stays (production `Start` delegates to it).

**Complexity.** Trivial.

### Task 3 — Relocate `lazy.setRNG` into `eligible_test.go`

**Description.** Move `(*EligibleSet).setRNG` (`internal/application/lazy/eligible.go:141-146`,
godoc included) verbatim into `internal/application/lazy/eligible_test.go` (already
`package lazy`, white-box). The `rng` field (`eligible.go:90`), its production reader
`RandomPath` (`eligible.go:104-109`, `e.rng.IntN(...)`), and the constructor default
`newCryptoSeededRand` all stay — production reads the field.

**Acceptance Criteria.**
- `setRNG` is defined only in `eligible_test.go`:
  `grep -rn 'func (e \*EligibleSet) setRNG' internal/application/lazy/` matches only the `_test.go`.
- The `rng` field and `RandomPath` remain in `eligible.go`.
- The 4 call sites (`eligible_test.go:320,335,346,365`) compile and pass unchanged.
- `make test` and `make lint` pass.

**Pitfalls.**
- `mrand` (`math/rand/v2`) stays imported in `eligible.go` — it is still used by the `rng`
  field type and `newCryptoSeededRand` (`eligible.go:228,235`). `eligible_test.go` already
  imports `mrand`, so no import change is needed on either side.
- Move only the setter method; the field it assigns is production-read and stays.

**Complexity.** Trivial.

## Execution Order

Tasks 1–3 are fully independent (different packages, no shared symbols) and may run in any
order or in parallel. Suggested order by blast radius, smallest first: **Task 3 → Task 2 →
Task 1**. After each task run the package's tests; after all three run `make test` and
`make lint` once, then the sanity build. Each task is its own atomic `refactor(<scope>):`
commit (`refactor(vpntunnel):`, `refactor(httpserver):`, `refactor(lazy):`).

## Risks

- **Accidental field drag (build break).** Moving a production-read field along with its
  setter breaks `go build`. Mitigation: the acceptance criteria pin exactly what stays; the
  criterion is "does production reference it at compile time," and every "stays" symbol has a
  named prod read site.
- **Unused-import fallout (Task 2).** Removing `StartOn` orphans the `net` import in
  `server.go`. Mitigation: explicitly move the import; `gofmt`/`go vet` in `make test` catch a
  miss immediately.
- **Wrong test-package boundary (Task 2).** Landing `StartOn` in the black-box
  `server_test.go` (`httpserver_test`) would not compile — it needs unexported-field access.
  Mitigation: create a white-box `_test.go` (`package httpserver`); acceptance criteria assert it.
- **Stale doc cross-references.** Low: repo docs reference these symbols in prose, not by
  production line anchor; no doc update is required.

## Trade-offs

- **Relocation over interface-ization.** Chosen deliberately (see the interface-ize section):
  an interface for any of these five removes no bespoke test-only *type* from prod and would
  either fork the composition-root wiring or add ceremony. The `Clock` seam already models the
  interface pattern where it genuinely pays off; the rest do not clear that bar.
- **Keep the trio as named helpers in `main_test.go`.** They could be inlined at each of the 9
  call sites, but that would churn the smoke test for no benefit; verbatim relocation keeps the
  call sites and the diff minimal.
- **`TunnelInfo` left untouched.** It is dead code (zero consumers), a stronger finding than
  "test-only," but deletion is a different concern out of this audit's scope; flagged, not acted on.
