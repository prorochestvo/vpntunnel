# Task Breakdown

## Overview

Stand up v1 of `httpproxy`: a forward HTTP proxy for Go clients (not browsers) that
egresses all traffic through a single static upstream SOCKS5 endpoint (the local
VPN client). Two request shapes must work end-to-end:

1. **Plain HTTP** — absolute-URI form (`GET http://example.com/foo HTTP/1.1`):
   we parse the incoming `*http.Request`, strip hop-by-hop headers, re-issue via
   an `*http.Client` whose `Transport.DialContext` dials through SOCKS5, and
   stream the response back to the client (status + headers + body).
2. **HTTPS via CONNECT** — `CONNECT api.example.com:443 HTTP/1.1`:
   we hijack the client connection, open a TCP conn to the target through SOCKS5,
   write exactly `HTTP/1.1 200 Connection established\r\n\r\n` back, then
   `io.Copy` bytes in both directions until either side closes or context cancels.
   No TLS termination — bytes are opaque.

The egress dialer sits behind a `tunnel.Dialer` interface so multi-tunnel routing
can be added later without surgery. In v1 there is exactly **one** implementation
(SOCKS5). No DB. No repository. No migrator. No client auth — bind to `127.0.0.1`
only by default. Config is JSON. Access logs rotate via lumberjack to `./logs/`;
operational logs go to stderr via `log/slog`.

Single binary: `cmd/httpproxy/`. No shared `bootstrap` layer — wiring is inlined
in `main.go` (per CLAUDE.md → Code Organization Principles).

## Assumptions

- **Module path: `httpproxy` (bare, no host).** The user confirmed this is a
  service binary that runs on a server, not a library — no external module will
  ever import it. Go accepts bare module paths; if vendoring or external import
  is ever needed later, a one-line rewrite of `go.mod` plus `goimports -local`
  fixes everything.
- **Go version: 1.23+** (we need `log/slog` mature, and `net/http` Hijacker
  semantics that are stable). Engineer pins the exact toolchain version when
  running `go mod init`.
- **SOCKS5 only as upstream in v1.** No HTTP-CONNECT chaining, no Shadowsocks,
  no WireGuard userland — that's all future work behind the same `Dialer`
  interface.
- **No HTTP/2 to the client.** Go's `net/http` does not support hijacking on
  HTTP/2; we explicitly disable h2 on the listener (`TLSNextProto = map[string]...{}`
  is moot since we don't terminate TLS, but we MUST refuse to start an h2
  listener — easy because we don't configure one). Plain HTTP/1.1 only on the
  client-facing side.
- **CONNECT target is `host:port`.** We do NOT resolve DNS locally — the SOCKS5
  upstream resolves the name (this is the whole point of routing DNS through the
  VPN). `proxy.SOCKS5` with `&net.Dialer{}` as forward is enough; we pass the
  hostname through unmodified.
- **Lumberjack v2 (`gopkg.in/natefinch/lumberjack.v2`)** is acceptable as the
  rotation engine. If a reviewer rejects the dependency we fall back to a
  hand-rolled rotator — out of scope for this plan.
- **`armon/go-socks5`** is acceptable as a *test-only* dependency to stand up a
  fake SOCKS5 server in `internal/tunnel` tests. If it's a hard no, we hand-roll
  a minimal RFC 1928 server (~80 lines) — note as a fallback in the task.
- **JSON over YAML, no env-only config.** Env vars may override a small subset
  of sensitive fields (e.g. `HTTPPROXY_UPSTREAM_PASSWORD`) but the canonical
  source is the JSON file. Document the override matrix in Task 2.
- **No metrics endpoint in v1.** Just structured access logs + operational slog.
  Prometheus/OpenTelemetry come in a later plan.
- **`internal.PublicError` lives at `internal/publicerror/`** or directly at
  `internal/` package root. Task 5 picks one and justifies — both are CLAUDE.md
  compliant.

### Task 2: `internal/config` — JSON loader, schema, defaults, validation

- **Description:**
  Implement `config.Load(path string) (Config, error)`. The `Config` struct
  lives **in `internal/config`** (not `internal/domain`) — config is an
  infrastructure concern with file I/O at its edges, and the domain package is
  pure types only. The `domain` package may later expose a *subset* (e.g.
  `domain.TunnelSpec`) but the on-disk shape stays in `config`.

  Schema (JSON tags lowercase):
  ```go
  type Config struct {
      Listen          string        // default "127.0.0.1:8080"
      UpstreamSOCKS5  Upstream      // required
      DialTimeout     time.Duration // default 10s
      IdleTimeout     time.Duration // default 90s
      ShutdownTimeout time.Duration // default 15s
      MaxConcurrentCONNECT int      // default 0 (unlimited); see Risk (c)
      AccessLog       AccessLog
      Operational     Operational
  }

  type Upstream struct {
      Address  string // "127.0.0.1:1080" (no scheme; we know it's SOCKS5)
      Username string // optional
      Password string // optional; env override: HTTPPROXY_UPSTREAM_PASSWORD
  }

  type AccessLog struct {
      Path       string // default "./logs/access.log"
      MaxSizeMB  int    // default 100
      MaxAgeDays int    // default 14
      MaxBackups int    // default 7
      Compress   bool   // default true
  }

  type Operational struct {
      Level  string // "debug"|"info"|"warn"|"error", default "info"
      Format string // "text"|"json", default "text"
  }
  ```

  Durations are JSON strings parsed via `time.ParseDuration` ("10s", "90s") —
  use a custom `UnmarshalJSON` on a wrapper type or unmarshal into `string`
  then parse. Recommended: define `type duration time.Duration` with
  `UnmarshalJSON` so the JSON file stays human-readable.

  Validation rules (return `internal.PublicError` for things the operator must
  fix; plain `error` for parse/IO failures):
  - `Listen` must parse as a valid `host:port`. Public: "config.listen: must
    be host:port".
  - `Listen` host of `0.0.0.0` or `::` logs a `warn` at load time — proxy has
    NO auth in v1. Not an error, just a warning printed via slog.
  - `UpstreamSOCKS5.Address` required, must be `host:port`. Public: "config.upstream_socks5.address: required".
  - Durations >= 0. Public message on each.
  - If `AccessLog.Path` is empty after defaults, public: "config.access_log.path: required".

  Commit a default `config/proxy.json`:
  ```json
  {
    "listen": "127.0.0.1:8080",
    "upstream_socks5": { "address": "127.0.0.1:1080" },
    "dial_timeout": "10s",
    "idle_timeout": "90s",
    "shutdown_timeout": "15s",
    "max_concurrent_connect": 0,
    "access_log": {
      "path": "./logs/access.log",
      "max_size_mb": 100,
      "max_age_days": 14,
      "max_backups": 7,
      "compress": true
    },
    "operational": { "level": "info", "format": "text" }
  }
  ```
- **Acceptance Criteria:**
  - [ ] File `internal/config/config.go` defines `Config`, `Upstream`,
    `AccessLog`, `Operational`, `Load`, plus exported defaults as `const`/`var`.
    Declaration order matches CLAUDE.md (exported consts → constructor `Load` →
    `Config` struct → exported methods (none here) → unexported helpers).
  - [ ] Every exported identifier has godoc starting with the identifier name
    and ending with a period.
  - [ ] `internal/config/config_test.go` has exactly one top-level
    `TestLoad(t *testing.T)` with subtests (run in parallel where possible):
    - `t.Run("loads valid file and applies defaults", ...)`
    - `t.Run("missing file returns plain error", ...)`
    - `t.Run("malformed JSON returns plain error", ...)`
    - `t.Run("empty listen returns PublicError", ...)`
    - `t.Run("invalid listen host:port returns PublicError", ...)`
    - `t.Run("missing upstream address returns PublicError", ...)`
    - `t.Run("negative dial timeout returns PublicError", ...)`
    - `t.Run("env override replaces upstream password", ...)`
    - `t.Run("bind on non-loopback emits warn but loads", ...)` — uses a
      `slog.Handler` captured into a buffer to assert the warn record.
  - [ ] `errors.As(err, &publicErr)` succeeds for every "operator must fix"
    case; plain errors wrap the underlying `os.PathError`/`json.SyntaxError`.
  - [ ] `config/proxy.json` is committed and loads cleanly via `Load`.
  - [ ] `make test` passes.
- **Pitfalls & edge cases:**
  - JSON does NOT support comments. If the engineer wants a documented sample,
    put it in `config/proxy.example.json` and load `proxy.json` as the runtime
    file — but in v1, one file is enough. Don't over-engineer.
  - `time.Duration` JSON round-trip is the classic Go footgun. The wrapper
    type's `UnmarshalJSON` must accept both `"10s"` (string) and `10000000000`
    (raw ns int) for forward-compat with `json.Marshal(d)`. Test both.
  - Env override happens AFTER JSON parse but BEFORE validation, so an env
    password satisfies a missing-in-JSON case. Document this order.
  - Resolve `AccessLog.Path` relative to the config file's directory? **No** —
    keep paths as-given (relative to cwd of the process). Document this in
    the godoc on `AccessLog.Path` so operators don't get surprised when they
    `systemctl start` and the log lands in `/`.
  - Loopback check: parse the host portion of `Listen` via `net.SplitHostPort`
    then `net.ParseIP`; the warn fires when the IP is non-loopback OR `0.0.0.0`/`::`.
    Hostnames like `localhost` resolve to loopback — accept without warn.
- **Complexity:** Medium
- **Code Example:**
  ```go
  type duration time.Duration

  func (d *duration) UnmarshalJSON(b []byte) error {
      // accept "10s" or raw nanoseconds
      if len(b) > 0 && b[0] == '"' {
          s, err := strconv.Unquote(string(b))
          if err != nil { return err }
          parsed, err := time.ParseDuration(s)
          if err != nil { return err }
          *d = duration(parsed)
          return nil
      }
      var ns int64
      if err := json.Unmarshal(b, &ns); err != nil { return err }
      *d = duration(time.Duration(ns))
      return nil
  }
  ```

### Task 4: `internal/tunnel` — Dialer interface + SOCKS5 implementation

- **Description:**
  Define the egress contract and implement it for SOCKS5.

  ```go
  // Dialer opens TCP connections to remote hosts. Implementations route
  // through whatever egress they represent (SOCKS5 in v1).
  type Dialer interface {
      DialContext(ctx context.Context, network, address string) (net.Conn, error)
  }
  ```

  SOCKS5 impl wraps `golang.org/x/net/proxy`:
  ```go
  type SOCKS5Dialer struct {
      address string
      auth    *proxy.Auth // nil if no creds
      forward *net.Dialer // controls dial timeout to the SOCKS5 server itself
  }

  func NewSOCKS5Dialer(spec domain.TunnelSpec, dialTimeout time.Duration) (*SOCKS5Dialer, error)
  func (d *SOCKS5Dialer) DialContext(ctx context.Context, network, address string) (net.Conn, error)
  ```

  Implementation note: `proxy.SOCKS5` returns a `proxy.Dialer` which does NOT
  have a `DialContext`. Cast it to `proxy.ContextDialer` (the x/net/proxy
  package guarantees this interface on the SOCKS5 dialer) and call
  `DialContext` so the context cancellation actually propagates. If the cast
  fails (shouldn't, but defensive), fall back to a goroutine + ctx.Done()
  cancel race — document the fallback in code.

  Username/password is optional; only set `proxy.Auth` if `spec.Username != ""`.

  Constructor is fail-fast: if `proxy.SOCKS5` itself returns an error (e.g.
  malformed address), `NewSOCKS5Dialer` returns it. It does NOT verify the
  SOCKS5 server is reachable (that's lazy — first real `DialContext` will fail
  with a clear error).
- **Acceptance Criteria:**
  - [ ] `internal/tunnel/dialer.go` defines `Dialer` interface and any shared
    sentinel errors.
  - [ ] `internal/tunnel/socks5.go` defines `SOCKS5Dialer`, `NewSOCKS5Dialer`,
    and `DialContext`. Compile-time check at file top:
    `var _ Dialer = (*SOCKS5Dialer)(nil)`.
  - [ ] `internal/tunnel/socks5_test.go` has exactly one
    `TestSOCKS5Dialer_DialContext` with subtests:
    - `t.Run("dials target through fake socks5 server", ...)` — spins up
      `armon/go-socks5` (or hand-rolled) on a random port, dials a
      `httptest.Server` through it, asserts the body round-trips.
    - `t.Run("returns error when socks5 server is down", ...)` — uses an
      unallocated port for the SOCKS5 server.
    - `t.Run("propagates context cancellation", ...)` — cancels ctx mid-dial,
      asserts `errors.Is(err, context.Canceled)` (or a wrapping error).
    - `t.Run("uses username and password when configured", ...)` — fake
      SOCKS5 with required auth, assert success with creds and failure without.
  - [ ] A second test `TestNewSOCKS5Dialer` for constructor input validation
    (empty address → error).
  - [ ] `make test` passes with `-race`.
- **Pitfalls & edge cases:**
  - `proxy.SOCKS5` ignores context unless you use the ContextDialer cast —
    miss this and `make test -race` will still pass, but in prod a slow SOCKS5
    server will leak the request goroutine until the OS TCP timeout. Audit the
    cast explicitly in code review.
  - `golang.org/x/net/proxy` puts `proxy.Auth` as a pointer; nil = no auth.
    Do NOT pass `&proxy.Auth{}` with empty strings — `proxy.SOCKS5` will then
    try to negotiate auth and fail.
  - The fake SOCKS5 server in tests must listen on `127.0.0.1:0` and report
    the actual port back; never hardcode a port.
  - Tests MUST close the SOCKS5 server in `t.Cleanup` to avoid leaking
    goroutines across subtests.
  - The `armon/go-socks5` dep, if added, goes into `go.mod` under `// indirect`
    only via tests — but `go mod tidy` doesn't tag it indirect because it's
    imported from `_test.go`. Acceptable: it lives in `go.sum` and as a normal
    direct dep. If reviewer rejects, hand-roll RFC 1928 (~80 LOC) in a
    `tunnel_test_socks5.go` helper file with build tag `//go:build test_helpers`
    or just leave it as a regular test file — simpler.
- **Complexity:** Medium
- **Code Example:**
  ```go
  func (d *SOCKS5Dialer) DialContext(ctx context.Context, network, address string) (net.Conn, error) {
      base, err := proxy.SOCKS5(network, d.address, d.auth, d.forward)
      if err != nil {
          return nil, fmt.Errorf("build socks5 dialer: %w", err)
      }
      cd, ok := base.(proxy.ContextDialer)
      if !ok {
          // defensive — x/net/proxy.SOCKS5 has implemented ContextDialer since 2019
          return nil, errors.New("socks5 dialer does not implement ContextDialer")
      }
      conn, err := cd.DialContext(ctx, network, address)
      if err != nil {
          return nil, fmt.Errorf("socks5 dial %s: %w", address, err)
      }
      return conn, nil
  }
  ```

### Task 5: `internal/publicerror` — the `PublicError` contract

- **Description:**
  CLAUDE.md mandates the `PublicError` wrapper. Spec says it typically lives
  at `internal.PublicError` but the project's `internal/` root is currently
  empty, and we'd rather have a real package than dump types in an
  `internal/internal.go`. Place it at `internal/publicerror/`:

  ```go
  // Package publicerror provides PublicError, the contract for errors whose
  // message is safe to surface to the proxy's client.
  package publicerror

  // Error is an error whose Details() are safe to send to the end user.
  type Error struct { details string }

  func New(details string) *Error
  func (e *Error) Error() string   // same as Details
  func (e *Error) Details() string

  // Is reports whether err is a public error (helper for callers).
  func Is(err error) (*Error, bool)
  ```

  All other packages import this as `publicerror` and call
  `publicerror.New("Invalid CONNECT target. Expected host:port.")`. The
  service layer is the typical creation site; the HTTP transport layer is
  the consumption site (it maps `*publicerror.Error` → response body, plain
  errors → fallback).

  Constant for the fallback message lives in `internal/transport/httpserver`
  (where it's used), not here.
- **Acceptance Criteria:**
  - [ ] `internal/publicerror/publicerror.go` defines the type and constructor.
  - [ ] `Error()` returns the details verbatim (no prefix).
  - [ ] `errors.As(target *publicerror.Error)` works.
  - [ ] `TestError` with subtests:
    - `t.Run("error returns details", ...)`
    - `t.Run("errors.As unwraps wrapped public error", ...)` — `fmt.Errorf("wrap: %w", New("x"))`.
    - `t.Run("Is returns false for nil and plain error", ...)`.
- **Pitfalls & edge cases:**
  - DO NOT embed `error` in the struct — keep it a clean leaf. If a future
    use case needs causal chaining, add a `Wrap(cause error, details string)`
    constructor that stores cause separately and implements `Unwrap()`. v1
    doesn't need it.
  - Constructor returns pointer so `errors.As(&target)` matches by type
    identity — the conventional shape.
- **Complexity:** Easy

### Task 6: `internal/observability` — slog setup + lumberjack access log

- **Description:**
  Two outputs:

  1. **Operational logger** (stderr, slog). Factory:
     ```go
     func NewOperationalLogger(cfg config.Operational) *slog.Logger
     ```
     Switches on `cfg.Format` (`text`|`json`) to pick the handler; switches on
     `cfg.Level` to set the leveler. Unknown level → default `info`, log a
     warn on the returned logger.

  2. **Access logger** — a small struct that owns a `*lumberjack.Logger` and
     an `*slog.Logger` writing to it in JSON format (access logs are for
     machines):
     ```go
     type AccessLogger struct {
         writer *lumberjack.Logger
         log    *slog.Logger
     }

     func NewAccessLogger(cfg config.AccessLog) (*AccessLogger, error)
     func (a *AccessLogger) Log(s domain.RequestSummary)
     func (a *AccessLogger) Close() error
     ```
     `Log` emits one JSON record per call with fields matching `RequestSummary`.
     `Close()` closes the underlying lumberjack file.

  The two are NOT merged — operational logs are human-readable on stderr;
  access logs are JSONL in a rotating file. Different audiences, different
  formats.
- **Acceptance Criteria:**
  - [ ] `internal/observability/operational.go` and
    `internal/observability/access.go` (two files, one per concern).
  - [ ] `NewAccessLogger` creates the log directory (`os.MkdirAll(filepath.Dir(path), 0o755)`)
    before opening the file. Returns a plain `error` if mkdir or open fails
    (not a `PublicError` — this is operator-facing on startup).
  - [ ] Compile-time check that `*lumberjack.Logger` implements `io.WriteCloser`.
  - [ ] Tests:
    - `TestNewOperationalLogger` with subtests for `text`/`json`/unknown-level.
    - `TestAccessLogger_Log` with subtests:
      - `t.Run("writes one json record per call", ...)` — temp dir, log 3
        summaries, read file, assert 3 JSONL lines that round-trip via
        `json.Unmarshal` into a struct matching `RequestSummary` keys.
      - `t.Run("creates parent directory if missing", ...)`.
      - `t.Run("Close closes underlying writer", ...)` — assert second Close is
        a no-op or returns ErrClosed-ish, but does NOT panic.
- **Pitfalls & edge cases:**
  - Lumberjack rotation hooks into `Write` — DO NOT call `Sync()` on it; not
    supported. Set `Compress: true` per config.
  - slog with a `JSONHandler` writes one record per `Log`/`Info`/etc. call —
    DO NOT manually `fmt.Fprintln` into the lumberjack writer; let slog handle
    framing.
  - Field names: use `slog.String("target", ...)`, NOT struct embedding —
    explicit keys are stable across refactors of `RequestSummary`.
  - The access logger MUST be safe for concurrent `Log` calls. slog's handlers
    serialize internally; lumberjack's `Write` has a mutex. So the composition
    is safe — but document it in godoc.
- **Complexity:** Medium

### Task 7: `internal/service` — `ProxyService` with `HandleHTTP` and `HandleCONNECT`

- **Description:**
  The brains. One file, one type.

  ```go
  type ProxyService struct {
      dialer       tunnel.Dialer
      httpClient   *http.Client   // built once, uses dialer for DialContext
      access       *observability.AccessLogger
      opLog        *slog.Logger
      idleTimeout  time.Duration
      dialTimeout  time.Duration
      connectLimit chan struct{}  // nil if MaxConcurrentCONNECT == 0
      tunnels      *sync.WaitGroup // for graceful shutdown
  }

  func NewProxyService(opts ProxyServiceOptions) *ProxyService
  func (s *ProxyService) HandleHTTP(w http.ResponseWriter, r *http.Request)
  func (s *ProxyService) HandleCONNECT(w http.ResponseWriter, r *http.Request)
  func (s *ProxyService) WaitTunnels(ctx context.Context) error // used by main on shutdown
  ```

  `HandleHTTP`:
  1. Reject anything where `r.URL.IsAbs()` is false (not a proxy request) →
     400 with `publicerror.New("Proxy expects absolute-URI request form.")`.
  2. Build a fresh `http.Request` via `http.NewRequestWithContext(r.Context(), r.Method, r.URL.String(), r.Body)`.
     Copy headers, then **strip hop-by-hop headers** (Connection, Keep-Alive,
     Proxy-Authenticate, Proxy-Authorization, TE, Trailers, Transfer-Encoding,
     Upgrade, plus any header listed in the incoming `Connection` header).
  3. Set `outReq.Host = r.URL.Host` (the upstream needs the target host, not
     ours). `RequestURI` is already empty on a request built by
     `http.NewRequestWithContext` — assert this in code.
  4. `resp, err := s.httpClient.Do(outReq)`. On error, return 502 with public
     message "Upstream unreachable." plus operational error log.
  5. Strip hop-by-hop on response too. Write status, headers, then
     `io.Copy(w, resp.Body)`. Track bytes via `io.Copy`'s return value.
  6. Defer `resp.Body.Close()`.
  7. Emit one `RequestSummary` to access logger after the response is done.

  `HandleCONNECT`:
  1. Parse `r.RequestURI` or `r.Host` (Go puts CONNECT target in `r.Host`).
     Validate `host:port`. On bad input → 400 + public message via plain
     `w.WriteHeader` BEFORE any hijack attempt.
  2. If `connectLimit != nil`, try non-blocking send: `select { case connectLimit <- struct{}{}: default: w.WriteHeader(503); return }`.
     Defer release.
  3. Dial target via `s.dialer.DialContext(ctx, "tcp", target)`. On error →
     502 with public message "Cannot reach upstream target.".
     **NOTE**: the response must be written BEFORE hijack — once hijacked, the
     ResponseWriter is dead. Strategy: dial first, hijack only on success.
  4. `hj, ok := w.(http.Hijacker)`; if !ok → 500 (this is an impl bug — the
     stdlib server supports hijack on HTTP/1.1). Log loud.
  5. `clientConn, bufrw, err := hj.Hijack()`. From here on, `w` is unusable;
     all writes go through `clientConn`.
  6. **Clear any deadlines** on `clientConn` (`clientConn.SetDeadline(time.Time{})`)
     — defaults from `http.Server` will kill long-lived tunnels.
  7. Write `HTTP/1.1 200 Connection established\r\n\r\n` via `bufrw.Writer`
     and `bufrw.Flush()`. EXACTLY that, no extra headers. Some clients are
     picky.
  8. Bidirectional copy: spawn two goroutines, `io.Copy(target, clientConn)`
     and `io.Copy(clientConn, target)`. When either returns, half-close the
     other direction (`CloseWrite` if `*net.TCPConn`) so the other side sees
     EOF. Track via `sync.WaitGroup`. Track tunnel in `s.tunnels` for shutdown.
  9. On `r.Context().Done()` (client disconnect detected by the server's
     read loop — but on a hijacked conn the context may not fire; in practice
     when the client closes the TCP conn, `io.Copy` returns naturally), close
     both conns so the copies unwind.
  10. Emit `RequestSummary` after both copies have returned.

  `WaitTunnels` blocks on `s.tunnels.Wait()` or `ctx.Done()`. Returns
  `ctx.Err()` if timeout fires first.

    plus a `Date:` and `Content-Length: 0` we don't want.

    fails, we've lost the ability to send a proper HTTP status. Order matters.
  - **Half-close on copy completion.** When `io.Copy(target, client)` returns
    (client done writing), we want the target to see EOF — call
    `target.(*net.TCPConn).CloseWrite()` if available. The conn from SOCKS5
    might NOT be `*net.TCPConn` directly (it's wrapped by x/net/proxy); type-

    request whose `RequestURI` is empty by construction. No manual clear

    break it silently.

    `client.CheckRedirect = func(*http.Request, []*http.Request) error { return http.ErrUseLastResponse }`.
    The proxy MUST NOT follow redirects — that's the client's job. Without
    this, a 302 from upstream becomes a transparent re-issue and the client
    never sees it.

    `io.Copy` MUST drain even on error so the underlying conn returns to the
    pool. If error, write a 502 and skip the copy.

    in-flight CONNECT count. Use a buffered channel as a semaphore. Document
    that this counts CONNECT only — HTTP requests are not throttled in v1.

## Risks

- **(a) SOCKS5 upstream down at startup.** Recommendation: **lazy-dial only**
  — `NewSOCKS5Dialer` validates the address format but does NOT open a TCP
  conn. First real request through the proxy is what discovers an unreachable
  upstream and surfaces it as a 502. Rationale: the proxy can legitimately
  start before the VPN client is healthy (systemd ordering varies; the user is
  the operator, not a cloud SRE team). The cost is a slightly slower first-
  request failure. We deliberately **do not** add a health endpoint in v1 —
  flagged as a future plan if operations needs it.

- **(b) CONNECT tunnels not draining on shutdown.** Accepted: `ShutdownTimeout`
  defaults to 15s; tunnels that don't close in that window are killed when the
  process exits. Logged at warn level so the operator sees abandoned tunnels.
  A long file download or websocket through CONNECT will be cut off — that's
  the cost of bounded shutdown. The user is single-tenant on a local box;
  acceptable.

- **(c) Memory under many concurrent CONNECT tunnels.** Each tunnel = 2
  goroutines + 2 `*bufio.ReadWriter` buffers (~64KB) + 2 TCP socket buffers.
  At 10k concurrent CONNECTs that's ~1GB of memory. `MaxConcurrentCONNECT`
  defaults to 0 (unlimited) — fine for the user's expected load (a handful of
  Go clients on one machine). Document the knob; suggest setting it to a sane
  number like 256 if the proxy starts serving more clients.

- **(d) Hop-by-hop list incompleteness.** RFC 7230 §6.1 enumerates the
  standard set, but the incoming `Connection` header MAY list custom hop-by-
  hop headers. We strip those too (see Task 7 acceptance). Risk is mitigated
  but not zero — a malformed proxy chain upstream could still leak data.
  Reviewer Lens B should re-verify this is handled.

- **(e) `http.Client` connection reuse across requests with different
  contexts.** The `httpClient.Transport.DialContext` uses the request's
  context, but Go's connection pool keeps idle conns alive past the request's
  ctx. If a later request reuses an idle conn whose underlying SOCKS5
  connection has died, we get a transient error and `http.Transport` retries
  silently. Acceptable. Document in the service's godoc.

- **(f) Missing TLS on the listener.** The proxy listens plain HTTP. Anyone
  with access to `127.0.0.1:8080` can issue arbitrary CONNECTs through the
  VPN. The bind-to-loopback default mitigates this. If the operator binds to
  `0.0.0.0` (we warn at startup), it's their problem until v2 adds auth.

## Trade-offs

- **Single static SOCKS5 vs. future tunnel pool.** Chose: one impl, behind an
  interface (`tunnel.Dialer`). Why: the user explicitly demanded extensibility
  without speculative implementation. The interface costs us one extra type
  declaration and zero runtime overhead; the alternative — inlining the SOCKS5
  client in `service` — would force a non-trivial refactor when multi-tunnel
  routing lands. Accepted: the interface is currently single-implementer,
  which CLAUDE.md flags as a yellow card; we believe the *imminent* (not
  speculative) multi-tunnel work justifies it. If multi-tunnel never ships,
  delete the interface and inline.

- **Lumberjack vs. journald/syslog.** Chose: lumberjack. Why: zero external
  daemon dependency, works identically on macOS dev machines and Linux
  servers, and the user wants the proxy to be a black box. journald would
  require systemd, which excludes macOS; syslog is half-supported on macOS
  and configures via system files. Lumberjack ships in-process. Cost: one
  more direct dep. If the team later runs this only on Linux servers with
  journald already collecting stderr, the access log can be re-pointed at
  stderr and journald can rotate — but that's a config-level change, not a
  code change. Future-proof.

- **HTTP/1.1 hijack vs. HTTP/2.** Chose: HTTP/1.1 only on the client side.
  Why: `net/http` does not support `Hijacker` on HTTP/2 streams — by design,
  per the stdlib. Without hijack, CONNECT cannot work. The Go clients we serve
  default `Transport.Proxy` for HTTP/1.1 anyway; HTTP/2 between client and
  proxy is rare. Cost: no h2 multiplexing between client and proxy. Acceptable
  — the *upstream* path through SOCKS5 can still negotiate HTTP/2 with the
  real target server (that happens inside the client's own TLS to the target).

- **JSON config vs. YAML/TOML/env-only.** Chose: JSON. Why: user explicitly
  hates YAML; env-only doesn't scale to nested config (lumberjack settings,
  multiple tunnel specs in v2). JSON is in the stdlib, no deps. Cost: no
  comments in JSON — mitigated by a separate example file if needed (deferred).

- **Composition root in `main.go`, no shared `bootstrap` package.** Chose:
  inline. Why: CLAUDE.md mandates this explicitly. There is exactly one binary
  in v1; even if v2 adds a second, the user's rule is to inline each binary's
  startup. Cost: when a second binary lands, ~30 lines of slog/lumberjack
  setup may be duplicated. We accept that cost; the alternative is a wiring
  layer that constrains both binaries to agree on dependency shapes.

- **No client auth.** Chose: defer to a later plan. Why: the threat model is
  "Go apps on this user's own machine"; loopback bind makes auth orthogonal in
  v1. Cost: if anyone runs this on a multi-tenant box without changing the
  bind, they're exposed. Mitigated by the startup warn. Auth work has its own
  plan when the user is ready.

- **`http.Server.WriteTimeout = 0`.** Chose: disable. Why: long-lived CONNECT
  tunnels are the entire point of the product; per-write deadlines would kill
  them. Cost: slow-write attacks against the forward-HTTP path are unbounded.
  Mitigated by `ReadHeaderTimeout` (limits the attack surface to the response
  copy) and the upstream `http.Client` timeouts (which DO bound the upstream
  side). Acceptable for loopback-bound v1; revisit when v2 adds auth and
  considers binding wider.
