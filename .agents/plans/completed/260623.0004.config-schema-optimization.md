# Task Breakdown

## Overview

`internal/config/config.go` has grown to ~970 lines exposing 15 `time.Duration`
knobs, several of which no operator ever tunes (async TTLs, async concurrency,
health handshake age), plus deployment-only TLS settings that belong on the
command line. The schema is also flat and unclear: top-level `listen`,
`upstream`, `auth`, `health`, `streaming`, `ondemand`, and proxy timeouts sit
alongside the `api` block, which itself mixes the HTTPS control surface with the
on-demand VPN proxy concern.

This plan reorganises the JSON schema **by concern** into a v6 shape, pushes TLS
settings to CLI flags, demotes never-tuned intervals to package-local constants,
decouples `httpserver` from the full `config.Config`, and — critically —
**splits the country-filter scope** so that `allowed_countries` constrains only
the always-on streaming pick while the on-demand scheduler may route to any
discovered zone.

This is a **deliberate breaking schema change**. Single host, one hand-authored
`proxy.json`, no fleet — acceptable. The migration UX is a set of precise
probe-rejections that name the new location of every moved/removed key, mirroring
the existing `config.admin` / `upstream.configs` rejections in
`config.go:90-108`.

The work is decomposed into **13 small waves**. Each wave is independently
compilable and leaves `make test` green on its own (a few config-package waves
leave the *module* build temporarily red until the matching `main.go` rewire
lands — those waves declare their scoped acceptance explicitly and their
dependent rewire wave restores the module build). Renumbered execution order and
explicit cross-wave dependencies are in the Execution Order section.

### Target schema (v6)

```json
{
  "vpnstream": {
    "listen": "127.0.0.1:8080",
    "allowed_countries": ["us","gb"],
    "auth": { "token_file": "./auth/token" },
    "reconnect_min": "10m", "reconnect_max": "3h",
    "dial_timeout": "10s", "idle_timeout": "90s", "shutdown_timeout": "15s"
  },
  "api": {
    "listen": "127.0.0.1:8888", "shutdown_timeout": "5s",
    "auth": { "admin_token_file":"...", "deploy_token_file":"...", "proxy_token_file":"..." },
    "vpn": {
      "async":   { "storage_path": "/opt/vpntunnel/state/async.db" },
      "demand":  { "grace":"10s", "settle_delay":"15s", "idle_ttl":"168h" },
      "timeout": "30s",
      "max_timeout": "5m"

    "log": { "path_sanitize_patterns": [] }

```

CLI flags (out of config): `-config`, `-tls-cert-dir`, `-tls-hostname`,
`-tls-ip-sans`.

| `api.tls` block | CLI flags `-tls-cert-dir` / `-tls-hostname` / `-tls-ip-sans` |

`api.max_request_body_bytes`, `api.log.*` keep their location and semantics.

## Assumptions

1. **Single host, one config.** No staged rollout, no format-compatibility
   window. A v5 config hitting a v6 binary fails fast with an actionable probe,
   never silently mis-parses (JSON ignores unknown fields → a forgotten probe is
   the worst failure mode).
2. **`operational` stays as-is** — explicitly NOT merged into `access_log`.
3. **`max_request_body_bytes` and `api.log.path_sanitize_patterns` stay under
   `api`** (not under `api.vpn`).
4. **(LOCKED) Empty streaming pool = startup error.** If `allowed_countries`
   filters out every config so the country-filtered streaming view is empty, the
   daemon FAILS to start with a clear publicerror. The streaming supervisor is
   NOT made optional — the "streaming owns exactly one live device for process
   lifetime" invariant (`supervisor.go:115-117`) is preserved. The on-demand
   view uses the FULL discovered set and NEVER gates on country.
5. **(LOCKED) `-tls-cert-dir` relative anchor = process cwd.** A relative
   `-tls-cert-dir` resolves against cwd via `filepath.Abs`, NOT against
   configDir. Production uses the absolute default `/opt/vpntunnel/tls/`, so the
   deployed host is unaffected. This is a behaviour change for relative cert dirs
   and is documented.
6. **The on-demand scheduler accepting any country is intentional and safe.**
   The single-key guard (`VerifySingleKey`) still runs over the FULL discovered
   set (`main.go:215`), so every `.conf` shares one WireGuard key regardless of
   country.
7. The `gocode-engineer` runs `make test` (race) after each wave; this plan does
   not re-derive test invocations. The `.claude/worktrees/*` copy is a sibling
   agent's scratch — ignore it, never edit or count it.

## Risks

1. **Empty streaming set panics `RandomPath`** (`eligible.go:108`, `rng.IntN(0)`).
   The LOCKED decision removes the risk: an empty country-filtered streaming set is
   a fatal startup error (Wave 9 builds it via `NewEligibleSet`, which returns the
   empty-set publicerror), so `RandomPath` is never called on an empty set and the
   supervisor stays mandatory. No supervisor-optional path is introduced.
2. **`httpserver.New` took the whole `config.Config`.** Renaming `Config` fields
   would have rippled into httpserver and its tests. Mitigated by Wave 7
   decoupling httpserver to `httpserver.Options` (three scalars) — turns a forced
   ripple into a deliberate, CLAUDE.md-aligned improvement.
3. **Partial migration leaves the tree uncompilable between waves.** Each config
   wave touches `Config`. Mitigated by landing 5→6→7 as a tight sequence and 4 as a
   single commit; Waves 5/6 declare their scoped (config-package-only) acceptance.
4. **Probe false-negatives** — a moved key the probe forgets silently no-ops (JSON
   ignores unknown fields) and the operator gets the old default with no warning.
   Mitigated by the exhaustive 18-probe enumeration (Wave 3 adds `health`; Wave 5
   adds the `upstream` move; Wave 11 adds the remaining 16 including all async-key
   probes) against the canonical key-move map, locked by per-probe tests. Wave 2 adds
   no probe (deferred to Wave 11 to avoid dead code), but the async keys it deletes
   are still covered — by Wave 11 probes #14-18.
5. **Probe false-positives** — probing a key that legitimately exists in v6
   (`api.listen`, `api.auth`, `api.vpn.async.storage_path`) would reject valid
   configs. Mitigated by probing only the matrix keys; the load-the-example guard
   test (Wave 12) catches a bad probe immediately.
6. **TLS cert-dir anchor change** — relative `-tls-cert-dir` now anchors to cwd, not
   configDir. Mitigated: production uses the absolute default `/opt/vpntunnel/tls/`,
   so the host is unaffected; documented in Wave 13 for anyone using a relative dir.
7. **`math` import accidentally dropped in Wave 2** — `asyncMaxJobsAbsent`/
   `asyncDurationAbsent` deletion tempts removal of `"math"`, but `lazyDurationAbsent`
   still uses `math.MinInt64 + 1`. Keeping the import is called out in Wave 2.

## Trade-offs

- **Two `EligibleSet` instances over two methods on one type** (Waves 8-9): chose
  two instances (`NewEligibleSet` filtered + `NewFullSet` unfiltered) because the
  type's single-`RandomPath`/`Lookup` contract stays clean and each instance has one
  filtering responsibility. Rejected adding `RandomPathFiltered`/`LookupFull` to one
  type — it would make the type carry two distinct eligibility notions and
  complicate its concurrency story. `NewFullSet` is a thin named wrapper purely for
  call-site readability + the never-country-gated doc; inlining
  `NewEligibleSet(…, nil)` would be behaviourally identical.
- **Decouple `httpserver` from `config.Config`** (Wave 7) over teaching it to read
  `cfg.VPNStream.*`: httpserver needs only Listen + two timeouts; depending on the
  full config was incidental coupling, and this refactor is the moment to remove it
  (CLAUDE.md "package placement follows consumption"). Cost: touching httpserver
  tests now. Benefit: a transport layer that no longer breaks every time config is
  reshaped.
- **Per-package constants (`internal/asyncjob`, `internal/tunnel/lazy`), not a
  shared `defaults` package** (Waves 1, 3): each value has exactly one consuming
  package. A shared defaults package would be a cross-cutting layer for
  single-consumer values — exactly what CLAUDE.md's "package placement follows
  consumption" forbids. `main.go` reading `lazy.DefaultHandshakeMaxAge` to wire the
  apiserver is composition-root wiring, not a new shared layer.
- **Keep `GCConfig`/`NewPool` injection seams** (Wave 1) over hardcoding the TTLs
  inside GC: the GC tests inject tiny TTLs to exercise transitions quickly. The
  constants are main.go-side defaults, not baked-in behaviour — testability
  preserved at zero API cost.
- **CLI flags for TLS over keeping them in config** (Wave 4): cert-dir/hostname/
  ip-sans are deployment-environment facts set by whoever launches the binary
  (systemd unit), not application config tuned in `proxy.json`. Cost: moving
  validation out of `config.validate` into `parseTLSOptions`. Benefit: a `proxy.json`
  that contains only application config.
- **Breaking change with no compatibility shim**: chose a hard break + precise probe
  rejections over a dual-read compatibility window because there is exactly one
  hand-authored config on one host. A shim would be dead weight for a fleet of one.
